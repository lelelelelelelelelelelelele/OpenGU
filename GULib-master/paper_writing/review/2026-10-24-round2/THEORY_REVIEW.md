## 1. 我理解的论文主张

论文固定候选训练节点、预算与评价协议，用 Random、结构选择、IM 以及两种损失敏感性评分构造不同删除请求。每个请求分别交给具体 GU 实现和匹配的 Retrain；研究者比较实际任务效用、相对随机请求的增量及 GU–Retrain 预测分歧，再检查预算与选点模型来源改变后的关系。

最有实质内容的主张是：

- **F-A：同一对请求的任务效用排序可能在 Retrain 与特定 GU 间相反。** Cora、SGC-source、10%、e79r6 中，D-full 相对 R-point 的 Retrain accuracy 高 0.849 pp，GNNDelete 低 5.756 pp，十个训练 seed 方向均交叉。这是经验结果，不是差分恒等式的必然产物。
- **F-B：选择策略改变同预算 Random 之上的 GU–Retrain 分歧，并与预算交互。** CiteSeer 的 R-point 在 GIF/MEGU 上给出较大的正 D_extra，而 Degree 不呈现相同方向；但相应 Retrain 自身明显退化，当前不能据此判定 GU 发生了额外破坏。
- 选集、Hop、来源比较界定这些关系的内容与适用范围；它们没有分别建立因果传播机制、目标模型泛化或第三项统一规律。

这是可以成立的经验论文类型。它不天然需要新定理、新 GU 算法或对非凸 GNN 的全局误差保证；需要的是操作定义与观测量一致，关键比较能够反驳某个明确判断，而且结果相对已有工作增加了足够具体的认识。

## 2. 已经具备的优点

1. **旧输出中的 F-A 不局限于一个离散指标。** 本轮直接读取[现有汇总表](../../../self/research/analyses/EXP-011_EXP-079/summary.csv)：同一 Cora/SGC/e79r6 条件下，R-point→D-full 的 Retrain test CE 均值为 0.399474→0.377197，GNNDelete 为 0.739863→0.920872。CE 也呈现与 accuracy 相容的端点反序；这是旧输出内部的次级描述，不是独立、干净的验证，不能抵消上述 checkpoint 选择风险。这里引用的是均值，尚未补逐 seed CE 配对区间。
2. v4 保留 Degree 更低的 GNNDelete accuracy、其他方法/数据集反例、四 source 的完整关系及探索性声明。这些限制不会消除主例的价值，反而使它可评估。
3. [原生 IF 附录](../../../report/paper/overleaf/sections/appendix.tex)已经交代 removal 正号、sum/mean 约定、last-layer、有限 shifted 迭代与 D-full 名称边界。当前不是完全没有方法定义；问题是这些限定如何进入主文的科学解释。
4. [有效性审查](../2026-10-24-self-audit/validity/VALIDITY.md)已有固定 checkpoint、Random 10% 的 no-update、参数写回、两图和数值残差证据。它们排除了一部分真实实现问题，不能在本轮被抹成“没有任何控制”。同样，原图/retained 图主例验证与三端点分析仍只是[准备好的方案](../2026-10-24-self-audit/VALIDATION_PLAN.html)，不是完成结果。
5. v4 已承认最接近 benchmark 覆盖普通 accuracy–fidelity 分离、非随机删除和 Original 参照，也区分了 source 变化与 target backbone 变化。相比把通用审计原则当新贡献，这个版本的定位明显更准确。

## 3. 七项高价值问题

### T1：中心问题把“不同目标”与“同一对请求的端点排序”混为一谈

**严重性：阻断当前中心论证；分类：写作可解＋现有数据分析。**  
位置：提纲中心论点、I-P2、I-P3、I-P4、Q1-P2、D-P1。

**最强质疑。** IM 覆盖率、R-point 点损失与 D-full 图修正源不是同一标尺。它们定义不同的目标，原本就没有一条应被保留的共同“重要性顺序”。而 F-A 测量的是 `U_R(S_D)−U_R(S_R)` 与 `U_M(S_D)−U_M(S_R)` 的异号，既没有比较两策略的目标分数，也没有验证由代理分数预测 GU 的规则。因此，“选择目标不能推导下游顺序”容易变成一个无需实验便知没有保证的命题。真正有内容的是：**用同请求 Retrain 的实际效用为这两类请求排序，在何种具体 GU 条件下会给出相反排序。** 这与“某代理的重要性估计失效”不是同一个问题。

**现有证据可以回应什么。** [直接对照](../2026-10-24-self-audit/analysis/source_strategy_contrasts.csv)与[交互表](../2026-10-24-self-audit/analysis/gu_retrain_strategy_interactions.csv)记录了明确的局部交叉；十 seed 同方向、幅度及 Degree 反例使它值得追查。它不是代数恒等式，也无需证明理论上“应该同序”才可能有经验价值。但它尚不能说明代理目标与真实目标之间的哪一步失配，作为科学证据使用还须通过新增的 GNNDelete Output 来源核验。

**最小修复。** 把主问题拆成两层：先定义“由哪些固定评分实例产生请求”，再定义“同一请求对在 Ret/GU 间的效用排序是否一致”。在完整比较家族中区分同向、反向与不确定，先给两条直接差，再给交互；负交互不单独作为反序证据。将“重要性目标→响应顺序”的宽泛句子改为可观察的两端点判断，不把事后整理包装成事前假设，也不需要发明新的预测理论。

**迫使降级的反结果。** 若其余条件大多不确定、同向，且交叉仅由一组实现/评价协议支撑，则主张应保留为该条件下的可复核反例，不能写成“重要性目标普遍无法预测 GU”。若两评价图或合理实现复核使主例消失，其角色须进一步降为协议敏感性案例。

### T2：验证 CE 代理与测试 accuracy 之间仍缺一条解释链，但 F-A 并非纯阈值假象

**严重性：重要；分类：写作可解＋现有数据分析；只有更强代理忠实性主张才可能需要新实验。**  
位置：M-P3、M-P5、I-P3、Q1-P2；[原生 IF 附录](../../../report/paper/overleaf/sections/appendix.tex)第43–100行。

**最强质疑。** IF 实际以验证节点集 Q 上的 CE 梯度为目标；结果主轴却是固定测试集 accuracy。即使单点影响估计准确、在 Q 上成功增大 CE，也不保证测试 accuracy 同序，更不保证特定 GU 的行为。若论文将这种跨目标不一致命名为“重要性失效”，它可能只是检验了从未成立的保证。D-full 的更完整 source 也不意味着它应比 R-point 在测试准确率上产生更大损伤。

**现有证据可以回应什么。** 上述现有 test CE 均值表明旧输出的 Ret/GNNDelete 交叉不局限于 0–1 accuracy；它仅回应指标离散化这个较窄问题，不能回应测试标签参与选 checkpoint 的风险。现有 032/053 还提供 Retrain 效用和部分匹配 GU 端点，但这些都不是“Q 上真实目标变化与评分预测吻合”的直接验证。测试 CE 也不能冒充选择时的验证 CE。

**最小修复。** 在主文说明 score 优化的是哪个集合、哪种 loss、哪个 source checkpoint；把测试指标定位为外部响应。先解决 checkpoint 选择的有效性门槛，不能通过继续加工 e79r6 CE 将 F-A 提升为干净证据。门槛通过后，逐 seed CE 才适合作为简短一致性检查。若仍要论证“代理目标是否实现/失真”，优先从既有评分与 Output 计算主例在同一 Q、同一评价图上的目标变化，保留预测代理值与实际值的区分；没有相应 payload 就明确未检验。无需把所有实验重跑成代理精度 benchmark。

**迫使降级的反结果。** 若 CE 不支持 accuracy 的方向，F-A 应限于分类决策效用；当前均值并未出现这个反结果。若代理在其自身 Q 上方向不准，则结果仍可支持“这些已实现评分产生的请求不同”，但不能支持对理想 IF、真实节点重要性或图影响近似质量的结论。

### T3：D-full 建模了单节点图耦合，但 top-k 请求仍采用可加近似

**严重性：重要；分类：写作可解；机制加强需现有模型/选集分析，缺资产时才考虑小范围新实验。**  
位置：M-P2、M-P3、R0-P1、Q2-P1/P2、附录 B-P1；[原生 IF 附录](../../../report/paper/overleaf/sections/appendix.tex)第79–100行。

**最强质疑。** IM 明确优化联合集合覆盖；IF 先在原 checkpoint 上为每个 v 计算一次分数，再取 top-k。对 IF，实际集合准则相当于最大化所选单点分数之和，而非在每一步重新计算删点后的边际影响。D-full 包含“单删 v”引起的保留节点损失变化，却没有因此解决同时删除一组节点时的邻域重叠、归一化变化与非线性相互作用。预算达 33%/50% 时，这个区分尤其重要。“图耦合损失请求”很容易被读成已经优化了整个删除集合的图耦合影响。

**现有证据可以回应什么。** 现有附录已准确写出 q_v 的两项 source、h=2 与参数子空间；选集重合和 032 的多个配置也说明不同实现能选出不同集合。它们没有直接度量联合删除梯度与单点 source 求和的偏差；Hop 覆盖也不能代替这种检验。这里不是要求把启发式改造成新算法，而是明确当前执行了什么。

**最小修复。** 在 M-P3 明写“原图单点评分、一次性 top-k、集合可加代理”，把 D-full 的“图耦合”限定在单点 source。解释 source、h、参数投影、有限求解和集合可加性是不同近似，不能由某一项通过来代表全部。若作者要把高预算关系解释为图耦合机制，只针对已选主例和一个反例，利用现有模型与选集检查联合删除源和单点源求和的差异；否则保留为策略实例的经验响应，不声称机制归因。

**迫使降级的反结果。** 若联合源与可加源偏差很大，或扩邻域/改参数范围使请求排名显著改变，应将高预算结果归于所用近似配置，不能宣称图影响目标本身具有该响应规律。相反，即使偏差较小，也只排除了一个替代解释，不自动证明 GU 差异的原因。

### T4：finite shifted selector 与 GU 数值校准是两个证据对象

**严重性：重要；分类：以写作可解为主；声称 IF 估计准确时需现有数据/模型诊断。**  
位置：M-P3、R0-P1、E-P5、附录 B-P1；[有效性审查](../2026-10-24-self-audit/validity/VALIDITY.md)；[原生 IF 附录](../../../report/paper/overleaf/sections/appendix.tex)。

**最强质疑。** `q_vᵀ(H+λI)⁻¹g_Q` 在展示上很像一个明确求解的 IF 对象，但实际使用 T=20、scale=25、damping=0.01 的有限递推，且原训练 checkpoint 未证明达到驻点。读者需要知道论文究竟研究“这个确定的有限评分器”，还是声称它忠实近似理论影响。固定 checkpoint 的 GIF/IDEA 更新残差控制不能给请求 selector 的这个方向背书；两者虽都出现 Hessian/shift，职责与参数不是同一件事。

**现有证据可以回应什么。** 附录已经写了条件推导和有限求解限制；R0-P1 又如实报告在历史选集矩阵中，P-point/R-point、P-graph/D-full 的重合超过99%。这对“目前 source 比曲率替换更影响选集”有用，也提示当前结果可能主要体现梯度/source 排序。四组 GU 校准中 shifted 残差小、原方程残差仍为0.1965–0.5559，确实区分了两个方程；不能说没有数值控制，也不能说已验证原 IF 理论。

**最小修复。** 主文直接以有限递推输出 `û_T` 定义实际评分，逆矩阵表达仅作为条件解释；将“IF-inspired”或等义的局部近似表述贯彻到结果。给 selector 与 GU 各自参数来源，保留历史选集证据的 checkpoint 身份。只有需要宣称 selector 的近似精度或曲率作用时，才补同 checkpoint 的 shifted residual/迭代稳定性及选集稳定性，不要求新定理或全参数精确 Hessian。

**迫使降级的反结果。** 若有限方向对迭代数不稳定，或梯度替换几乎完全保留关键请求，应撤去“逆 Hessian 揭示了特殊机制”的表述；仍可报告固定评分实例的请求关系。若其排序稳定，即使原方程近似不足，也不会自动推翻 F-A 的经验端点比较。

### T5：D_extra 的新价值取决于它刻画哪一端的响应，而非差分名字

**严重性：重要；若声称 GU 特有破坏/遗忘失败则为阻断；分类：现有输出分析，R–R 新训练仅对更强主张有条件必要。**  
位置：M-P5、Q2-P2、D-P2、附录 A-P4；[有效性审查](../2026-10-24-self-audit/validity/VALIDITY.md)。

**最强质疑。** 两个 D 各自使用不同请求下的 Retrain，因此减去 Random 不会把 D_extra 变成 GU 自身额外变化。R-point 可能主要使 Ret 退化，而 GU 保持 Original；这仍是有意义的响应分离，但与“战略请求诱发 GU 预测破坏”有不同含义。若发现只剩下“删掉更多对训练有用的点，Ret 下降而小更新 GU 不动”，相对近邻已经观察的预算分离，新增解释需要更具体。

**现有证据可以回应什么。** v4 已把 CiteSeer R-point 的 Ret accuracy 75.275%→64.715% 与 GIF/MEGU 端点放在同处，也有 Degree/Random 和 Cora/GNNDelete 负 D_extra 反例；不能说它隐藏了 Ret。已有 Random10% no-update 控制排除了部分格子的精确零更新，但不覆盖战略主例、高预算和 MEGU 的 C&S 组成。当前三端点/两图/匹配 C&S 仅有输入绑定与执行方案。

**最小修复。** 优先完成已有计划中的 `D(O,GU)`、`D(O,R)`、`D(GU,R)`、相应效用与节点三方关系，MEGU 使用匹配后处理。按结果写“GU移动”“Ret移动”或“两者响应分离”；若暂不完成，维持观察性 D_extra，避免给它新增机制名。固定请求 R–R 只在声称超过自然重训波动、异常遗忘偏离时才是必要补强；无需为描述性 D 强制启动新训练。

**迫使降级的反结果。** 若 GU 近似 Original、Ret 明显移动，应撤去 GU 自身被破坏的解释；若 MEGU 主要由 C&S 改变，则限于 pipeline 行为；若评价图改变使关系消失，限于原图协议。以上不会自动让现有 D 数值失效，但会改变它对新颖性与风险的意义。

### T6：全训练池权限、可见信息与原图评价必须对应一个可信的 Web 问题

**严重性：重要；分类：写作可解；只有真实用户攻击/部署外推才需新实验。**  
位置：I-P1、P-P2、P-P3、M-P4、D-P3。

**最强质疑。** “贡献者撤回记录”的例子对应受所有权限制的候选池，而当前选择器能从全部合格训练节点挑选，还可能使用训练/验证标签及模型梯度。这可以是平台审计者的压力测试，却不是一个普通请求者自动拥有的能力。另一个语义跳跃是：训练侧移除监督与 incident edges，但测试重新使用原图及特征；它不能直接回答永久移除这些数据后的平台服务行为。若以普通用户合法请求开场、以管理员级候选池得出风险结论，权限和部署语义会错位。

**现有证据可以回应什么。** v4 已明确全池是权限上界、GCN-source 不等于所有 GU 的白盒，也写明特征行保留与原图测试；这些是实质修正。它还提出“平台仅依赖 Random 评估会漏掉什么”的受控问题，这是较可信的 Web 定位。大图 selector 成本证明部分请求构造可以运行，但没有平台 GU 端点或真实权限约束证据。

**最小修复。** 统一主语为平台评估者/授权压力测试者，逐策略给出实际信息、候选资格和查询需求；不能把信息表当作可有可无的装饰。区分“符合实验候选规则”与“用户真实拥有撤回权限”。第一页明确图依赖为何使请求选择影响更新评估，说明本研究支持测试设计中的何种具体判断。原图语义在主文保持可见；现有模型的 retained 图检查可检验最直接的部署敏感性，无需为贴 Web 标签强加一个大数据集。

**迫使降级的反结果。** 若关系只在全池/充分标签访问下出现，应保留为强权限压力测试，撤去普通用户攻击风险外推。若原图与 retained 图结论相反，必须把部署判断与本研究的原图诊断分开，不能靠“双方同图所以公平”消除语义差异。

### T7：相对近邻的贡献已收窄，但还需要证明“新增认识”超过新增策略行

**严重性：阻断贡献强度判断，新增有效性风险须先核清；分类：写作＋现有数据/来源分析；若污染绑定成立，维持 F-A 需合规 checkpoint 下的重新验证。**  
位置：I-P4/I-P5、RW-P1/P2、Q1–Q3、Conclusion；[此前近邻原文定位核验](../2026-10-24-self-audit/positioning/CRITIQUE.md)。

**最强质疑。** 按已有原文核验，近邻已研究预算下的 accuracy–fidelity 分离、degree/class 请求和 Original 参照；其他工作已有请求者建模、代理模型以及注入后删除。本文采用 IM/IF、做同请求配对并增加差分，分别都是可解释的选择，但相加不自动形成足够的新贡献。若最终结论只剩“策略效果依条件变化”，它过于宽泛；完整矩阵的工作量也不能替代科学增量。

**现有证据可以回应什么。** F-A 展示较大且训练 seed 方向一致的 Ret/GNNDelete 交叉，四 source 的负交互延伸了局部关系；F-B 展示同预算 R-point 与 Degree/Random 的方向区别及预算交互。这些比旧主张强，值得保留。与此同时，F-A 主要依赖 Cora/GNNDelete，四 source 不等于独立 target 泛化；F-B n=3，且三端点归因未完成。source margin 主要由 GNNDelete 驱动的事实是范围说明，不能单独补成第三项贡献。

新增源码风险进一步改变证据优先级：若 F-A 所用 GNNDelete best checkpoint 确由 test-mask 指标选择，该输出不再提供独立测试端点。固定 seed 配对或 Ret 参照不会抵消它，因为不同请求可能改变被选中的训练轮次及选择偏差。该事实不能推出 F-A 必然是假，也不能推出泄漏一定制造了特定方向；它意味着当前数据不能确定干净协议下该关系是否保留。当前源码事实已经核对，具体主例缓存来源须由溯源结果确定。

**最小修复。** 先绑定 F-A 的具体 Output、producer 与 checkpoint 选择路径。若风险绑定成立，隔离 F-A，检查是否存在预先定义且未使用测试标签选择的可恢复 checkpoint；仅在这种资产足够时可先复算，否则维持该主张需要遵循正式流程重新验证，不能通过重命名指标解决。有效性通过之后，用两条可核查的句子列贡献：第一条说哪一类请求对、在哪个目标条件出现 Ret/GU 反序；第二条说哪一策略相对 Random/Degree 的额外分歧如何随预算改变，并带方法/数据集边界。研究设计作为支撑合并为一项，来源与空间作为边界分析。正文保留关键反例，说明这些关系改变了哪一种具体评估判断；独立 split 或目标模型只在进一步泛化确有需要时考虑。

**迫使降级的反结果。** 若 GNNDelete 溯源确认使用测试指标选 checkpoint，且没有干净复核，F-A 必须退出主要科学贡献；若干净复核不保留交叉，也不能继续沿用旧均值叙事。若补充诊断后 F-B 只是已知预算分离在一种请求下幅度更大，且没有可解释的新增条件关系，它应降为对已知现象的扩展验证。若 F-A 只在某个实现/图协议成立，应把该边界写进贡献；若这样收窄后已不足以提供有分量的新认识，不能通过改标题、增加报告术语或扩大矩阵数量补救。

## 4. 什么会改变我的判断

我不会因补了一条定理、加了一种 GU、或把所有诊断清单打勾就转为接受。最有帮助的是三个具体变化：

1. **有效性先于主张增强，主问题对齐观测量。** 先核清 GNNDelete checkpoint 的具体来源并处理受影响证据，再以清楚的 Ret/GU 请求对排序与策略特定预算响应为经验问题；代理目标的忠实性若未检验，就不让它承担主结论。旧输出 CE 不能替代独立测试有效性，也不能默认测试 accuracy 等价于验证目标。
2. **最关键替代解释得到有范围的处理。** 完成主例已有 Output 的三端点、两图与匹配后处理分析，或者依据无法完成的范围明确降低结论。有限 solver、单点 top-k 与联合删除之间的近似关系写清后，不需要补无关的理论大工程。
3. **两条贡献经过完整条件范围后仍有实质内容。** F-A 的量级与方向保留，F-B 确实给出相对已有 benchmark 更具体的策略条件关系，并能说明对平台测试设计的实际含义。若只剩一个脆弱后验案例，应坦诚降低论文野心。

满足前两项会使论文更可评审；第三项决定我是否从 Weak Reject 转向 Borderline 或 Weak Accept。若新增风险绑定成立而未清除受影响主张，当前拒绝倾向会加强。v4 原有数值提供了值得追查的线索，尚不能在新的有效性疑问下直接提升为录用理由。
