把删除请求当作攻击面：一套可证伪的 GNN Unlearning 审计框架

这次汇报以 experiment setup 为主轴：如何定义一个 cell，如何组织 method × selector × scope × metric，如何用 random 与 exact retrain 建立对照，以及如何把一次运行变成可复核证据。

QUESTION删除请求是否可以成为 approximate unlearning 的攻击面？
SETUP对象、cell、矩阵轴、对照和证据层构成汇报主体。
EVIDENCEResults 后置，只展示有范围边界的证据样例。
ONGOINGCache、TracIn、surrogate 只在最后的 Next steps 出现。
Problem

为什么做：删除请求不是天然无害的输入

Graph unlearning 关注如何忘记指定数据；本项目额外审计谁来指定、指定哪些数据，以及 approximate unlearning 是否会放大这次删除的损失。

如果 deletion set 由攻击者在固定预算下策略性选择，近似遗忘是否会产生比 exact retrain 更大的额外损失？
01

效应

哪些 deletion sets 会让模型性能下降？结构中心性、传播覆盖和模型 sensitivity 是否指向同一批节点？

02

归因

下降来自删除集本身，还是 approximate unlearning 相对 exact retrain 的额外误差？

03

机制

不同 GU family、selector 信号和访问权限为什么呈现不同的 vulnerability fingerprint？

本次口径：目标不是证明 IF / IM 永远最强，而是希望通过一套能被反例推翻、能区分失效来源的 systematic audit，寻找不同 selector 与 GU family 响应背后的可解释性。
Setup

完整实验框架：对象解耦、矩阵展开、exact retrain 归因

这是汇报主体。结果会变，框架回答的问题不应跟着每个 cell 摇摆。

2.1 两类对象必须解耦

Execution object

GU Method

收到 deletion set 之后，怎样更新、分片、近似或重训练模型。

GIFGNNDeleteMEGUIDEAGraphEraserGraphRevoker
Request object

Deletion Selector

固定删除预算下，怎样选择进入 request 的有序节点集合。

randomdegreePageRankIMTracInHybrid

2.2 一次 cell 的完整执行链

01Train训练 base GNN，固定 split、seed 和 model identity。
02Select在 train candidate pool 中产生有序删除集合 T。
03Unlearn目标 GU method 接收相同 T 执行删除。
04Retrain移除 T 后从头训练，作为 exact reference。
05Evaluate比较 utility、gap、collateral 和 detectability。
06Prove保存 prediction、metadata、recipe 与 acceptance。

2.3 四条矩阵轴

METHOD
不同 GU family 如何失效？

influence / learning / partition-shard 不是同一种近似。

SELECTOR
攻击信号来自哪里？

random、结构 volume、propagation、model sensitivity、fused proxy。

SCOPE
现象能外推多远？

dataset × backbone × ratio × seed 决定 claim 边界。

METRIC
“失效”究竟指什么？

F1、retrain gap、collateral、update-detection AUC、效率。

2.4 归因公式：Total 不是全部漏洞

Total = Drop_retrain + Gap
      = (Perf_before - Perf_retrain)
      + (Perf_retrain - Perf_unlearn)
分量定义研究角色
Drop_retrainExact retrain 也会出现的下降Deletion set 本身的难度与应有损失
GapPerf_retrain − Perf_unlearnApproximate unlearning 的额外损失 / over-forgetting
TotalPerf_before − Perf_unlearn表面总下降；单独使用无法做机制归因

2.5 指标各司其职

指标回答什么边界
Raw / paired F1模型性能是否变化会混入 deletion set 本身损失
Retrain gap近似遗忘是否额外过度遗忘当前主归因指标
Collateral / prediction flip保留节点受到多大波及必须和 exact retrain 对照
Update-detection AUC一次更新是否暴露被删集合不是标准 shadow-model MIA
Selection / end-to-end time攻击各阶段资源代价selector 与 MIA / retrain 成本分开

4.1 七个实验块，对应七个检测问题

它们不是单纯的配置分类，也不是七组同等优先级的结果。完整框架先检查 selector 信号是否成立，再刻画核心脆弱性，随后检查机制、scope 与规模外推；sanity 则负责阻止执行错误混进研究结论。

01 / SUPPVALIDITY

Selector 信号真的不同吗？

检测 IM 是否只是 degree、proper TracIn 是否接近 GIF，以及 deployed TracIn 是否需要刷新。先确定“选点信号是什么”，才能解释后面的攻击差异。

关键对照Top-k overlap；GIF / proper / deployed TracIn；必要时 LiSSA sensitivity
02 / CORACORE

核心 vulnerability fingerprint 是什么？

在统一主矩阵中检测不同 GU family 的异质响应，以及不同 deletion signal 是否触发不同脆弱性。

关键对照同 scope / ratio / seed；budget-matched random；exact retrain
03 / ARXIVSCALE

小图规律能扩展到大图吗？

检测 Cora 等小型 citation graph 上的响应形状是否能跨 graph scale 保持，而不是 small-graph artifact 或计算路径特例。

关键对照保持 selector 语义、指标与基线一致，只放大 graph scale
04 / A3MECHANISM

IF–IM 融合有独立机制吗？

检测 Hybrid 是产生互补信息，还是只在 IF 与 IM 两个端点之间做数值插值；alpha 是诊断轴，不是默认主贡献。

关键对照固定 scope，比较 α=0、中间值与 α=1 的响应曲线
05 / A5ROBUSTNESS

结论只属于一个预算或数据集吗？

通过 ratio sweep 与 dataset transfer 检测现象是否只是 one-budget、one-dataset anecdote。

关键对照改变 ratio / dataset，其余 cell 坐标尽量固定
06 / A6BACKBONE

结论依赖某个 GNN backbone 吗？

检测响应是否由 GCN / GAT / GIN 等架构归纳偏置驱动；未运行时保持 deferred，并明确外推边界。

关键对照只改变 backbone，固定 dataset、ratio、method、selector 与 seed
07 / SANITYGUARDRAIL

实验路径本身有没有坏？

在最小闭环里检查 runner、GU method、selector、cache 和 artifact completeness。它只负责拦截工程错误，不能被升级成 paper evidence。

关键对照单 cell、已知期望、完整 artifact 与 acceptance gate
SUPP signal validity → CORA core fingerprint → ARXIV + A5 + A6 generality → A3 mechanism · guarded by SANITY

4.2 一个 cell 的坐标

cell = (dataset, backbone, ratio)
     × GU method × selector × seed
SC

Scope

  • Dataset / backbone / ratio
  • 控制图规模、归纳偏置和删除预算
  • 决定结论能够外推多远
GU

GU method

  • 控制 approximate unlearning 机制
  • 比较不同 family 的响应形状
  • 读取 family-level heterogeneity
T

Selector

  • 固定预算下构造有序删除集合
  • 区分结构、传播和模型信号
  • 读取 attack-signal sensitivity
S

Seed

  • 覆盖训练、划分与选择随机性
  • 报告均值、方差和方向稳定性
  • 防止单 seed 升级成机制结论

4.3 一个结论需要哪些对照

对照作用不可替代的原因
Budget-matched random同预算、同 seed 的 paired baseline判断策略性选点是否优于随机删除
Exact retrain without T删除同一集合后的金标准分开删除集损失与近似算法额外误差
Multi-seed repetition估计均值、方差与方向稳定性阻止单 seed 现象升级为机制结论
Noise anchor（可选）估计极小删除的固有波动只作参考线，不替代 budget-matched random

4.4 证据产物分层

L1 · SELECT
有序 selected_nodes + selector 配置

删除集合由什么信号、预算和候选池生成。

L2 · PREDICT
Before / unlearned / retrained logits

三个模型状态能否复算并在同一节点空间对齐。

L3 · EVAL
F1 / gap / collateral / detection

失效是性能下降、近似误差还是副作用。

AUDIT
Config / git SHA / seed / scope

结果来自哪套代码、实验身份与验收边界。
