我做的七项关键改进

每项改动都对应旧系统的一类结构性歧义。

原问题架构决策得到的能力
实验坐标与执行次数混在文字里cell_id 与 run_id/attempt 分离，配置与代码单独 fingerprint能区分重试、重跑和实验定义变化
平面 OK/X 无法描述部分完成selection / attack / collateral / run 状态机知道具体停在哪个阶段
Cache HIT 语义模糊类型、来源、Recipe、Artifact、authority、write outcomeCache 事实可追溯，不夸大历史复用
retry 与重复条目无法关联新 run、递增 attempt、retry_of、稳定 dedup保留失败历史，同时压缩真正重复
并发 writer 可能互相覆盖视图append 与 refresh 共用排他锁投影不会倒退到旧事件
旧日志无法满足新 schema逐字节冻结 archive + curated baseline保留历史但不制造 V3 完成态
Markdown 既是数据又是页面JSONL 权威 + projector + bounded MD/HTML页面可重建，审计事实不依赖页面

身份模型

  • cell_id：稳定实验坐标
  • run_id：一次真实执行
  • attempt/retry_of：失败链路
  • config_fingerprint/git_sha：运行语义与代码来源

Cache 真值规则

ResultCache 整体命中时，只报告本次 result reuse；不会把缓存对象中的历史 SelectionCache HIT 重放成本次 selection 事实。

4

真实探针暴露并修掉的终态漏洞

这是本次改进最重要的闭环：事件系统不只记录事实，还必须拒绝互相矛盾的事实。

旧矛盾序列：producer 已写 attack.failed，但因为返回码仍为 0，runner 继续 collateral，最后又写出 run.completed。
1 · Producer无结果或 strategy failed 时，记录失败后非零退出。
2 · Runner检查 rc，也检查 attack.json 是否非空、含目标 strategy 且未失败。
3 · Event store非 run 阶段失败后，拒绝 completed / skipped 终态。
4 · Projector对历史矛盾流采用 failure-first，保留原字节但显示 failed。

修复前

attack.failed → collateral → run.completed

问题不是页面显示错误，而是 orchestration、事件合同和投影规则没有共同守住终态。

修复后 · attempt 3

attack.failed → run.failed → STOP

Legacy Cache freeze 再次导致无 attack result；没有 collateral，没有 false completion。

5

现在成立的设计保证

这些是架构承诺；测试数字只在下一节证明它们。

身份与重试

  • 同一 cell 的 attempts 可区分
  • retry 显式链接上次失败
  • 配置与代码来源独立记录

终态一致性

  • 阶段失败不能伪装成整次成功
  • 冲突 terminal transition 被拒绝
  • 历史矛盾在投影时失败优先

审计与 Cache 真值

  • JSONL 是唯一机器权威
  • Cache 来源、Recipe、Artifact 可追溯
  • Legacy 永远标注 non-authoritative

恢复与并发

  • MD/HTML 可从事实重建
  • 坏流 fail-closed
  • append 与 refresh 锁内串行

已知边界

这些不推翻本次架构结论，但属于后续演进需要继续守住的约束。

#边界
1append 前仍线性扫描并验证 JSONL；未来索引必须能从 JSONL 重建。
2pre-fix 的矛盾 attempt 保留为不可变审计证据；projector 显示 failed，attempt 3 提供运行修正。
3standalone producer 与 runner-managed attempt 的语义压缩规则必须持续区分。
4AutoReport 保证事实与状态正确，不保证某个具体实验一定成功。
Architecture outcome

我完成的不是报告模板美化，而是职责拆分：AutoReport 已从“把运行文本追加到 Markdown”，演化为“带统一身份、阶段状态机、Cache provenance、终态约束和可重建视图的实验审计系统”。
