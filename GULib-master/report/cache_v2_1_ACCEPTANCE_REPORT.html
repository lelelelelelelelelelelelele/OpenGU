3. 机器契约

Recipe

dict key 排序无关；list/tuple 保序；float 使用有限十六进制形式；Path 带 kind；Enum 使用 module + qualname + value；Unicode NFC。NaN/Infinity、set、非字符串 key、未知类型与实验 ownership 字段拒绝。

Header 与 producer

ArtifactHeader v1 只含 metadata，不含 payload。Producer 同时支持 semantic version 与 source fingerprint；正式 valid Artifact 至少具备一种 producer identity 且必须 verified。

状态

Artifact：valid / degraded / invalid / corrupt / missing / retired / unknown / conflict。Verification 独立为 verified / degraded / invalid / corrupt / missing / unknown。

冲突

同 Recipe + 同 content 幂等；不同 content 要求 baseline，进入 conflict/quarantine 记录，原正式 Artifact 不覆盖，Resolver fail closed。

7. V2.2 gates

  1. 评审并冻结 Score/Selection 最小 Recipe 与 Legacy promotion policy。
  2. 决定 header carrier 与 semantic directory，并验证 payload/header 可重建 index。
  3. 人工裁决唯一 conflict；Resolver 不得猜测。
  4. unknown/degraded source 的 provenance 未补齐前不得 promotion。
  5. 先在隔离 index 完成 Score/Selection canary，再讨论主查询路径。
  6. runner 接入另立变更，继续保持 Legacy 只读并提供旧路径回归证据。

仍未完成：真实 Legacy --apply、正式 payload/header store、promotion、compatible/prefix、runner 接入、repair、retire、GC 与任何 payload 迁移。这些都不是 V2.1 的隐含完成项。
