1. 白盒边界：问题不在 validation CE → test F1

validation CE 用来构造 selection target、test F1 用来做最终评价，是合理的防泄漏设计。真正的白盒条件是：打分与 GU 必须指向同一份 pre-unlearning checkpoint。

层级模型关系能够回答
Target-direct white-box同一 checkpoint；文件 SHA-256 与 state hash 完全一致selector 对实际被遗忘目标是否有效
L1 surrogate transfer同任务、相关模型族，但结构超参、训练或 state 不同ranking 能否迁移到另一个目标模型
更强 transfer模型族或任务也不同跨模型/跨任务迁移

旧配置期望/实际删除数为 Cora 135/7、CiteSeer 166/7、PubMed 985/7。旧代码只 warning 后继续；新 formal 模式对此直接失败。

2. 新实验合同

Canonical 数据与无泄漏 split

  • source 只允许 SSH active checkout 的 data/raw/<dataset>/；OpenGU pair 只允许 data/processed/transductive/。
  • 固定 planetoid_70_10_20_seed2024，train/validation/test 互斥且穷尽。
  • 全图 message passing；train-only candidates；validation-mask mean CE target；test labels 只用于最终 F1。

80/0/20 的 validation mask 为空，因此不能继续作为本轮 IF/TracIn target profile：使用 test 会泄漏，复用 train 会改变科学问题。
