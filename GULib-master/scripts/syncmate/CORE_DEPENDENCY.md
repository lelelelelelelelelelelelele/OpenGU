# Installed execution dependencies

Explicit SyncMate integration requires the exact Core and OpenGU control payloads
in core_dependency.json and control_dependency.json. Native execution imports
neither control nor Core. Pins bind version, wheel SHA-256 and complete payload
hashes; RECORD/generated bytecode are installation metadata.

Core 0.7.1 includes the accepted SM-026/SM-028 implementation plus SM-029's
historical output-reservation admission fix. Source candidate
`a1802994f300a7def29afe7b7b57e703699d1cf9` is merged locally as
`6b591b9bf361d38140c22047021e5cb042fec0ac`; no public push or release is required
for this private deployment. The exact wheel digest and full payload list live
in `core_dependency.json`. OpenGU control 0.2.1 changes only its package version
and exact Core requirement; scientific code and historical evidence are unchanged.

The small opengu-syncmate wheel installs only the control bridge outside the
execution checkout. It embeds Core APIs, not another queue/lease/supervisor/source
store/transfer protocol. Build with repository pyproject.toml/setup.cfg; record
and verify the actual wheel and payload identities before an authorized install.

The source CLI launches python -I -X utf8 -m opengu_syncmate with an explicit root.
On Windows automated child creation uses CREATE_NO_WINDOW, as Core peer invocation
does. Mixing launch modes on the tested Windows machine changed platform.platform()
build reporting and Core refused environment equality. The failure is preserved;
no environment values or equality checks were patched. Linux process behavior requires separate observation.

Binding reads selected Git Python defaults and YAML in a fresh committed-file
worker, with no mutable-project import fallback. Startup preloads installed
control/Core then runs scientific checks from the exactly prepared checkout.
Pins, source SHA, scientific readiness, hardware and runtime/output identity must
pass before producer launch.

Core owns run-handoff/v2, node status, source preparation, contained processes,
seals, checksum transfer and trusted index. OpenGU freezes its scientific
declaration under the Core recipe digest and invokes the original Git validator
through scientific-check. Transfer, project validation and scientific acceptance
remain separate.

The registered bootstrap installs only the accepted wheel pair into immutable
project venvs inheriting the scientific base. It never modifies the Core 0.6 base
packages, CUDA, Python or drivers. The single shared source update still requires
all physical node queues to be safely idle. Offline endpoints are deferred and
verify/install the same staged pair upon returning, before receiving a job.
No queue/handoff migration or automatic repair is provided. See README.md and
bootstrap.action.json / install.action.json for the registered boundary.
