# E7 两组代理选集迁移实验计划

## 1. 研究问题

E7 研究的是攻击者无法访问 victim backbone 内部参数时，能否在 surrogate 上生成删除选集，并将同一选集迁移到未知 victim。它首先是 black/white-box access boundary 下的 query-free 灰盒迁移实验，而不是预设 surrogate 选集必须进一步放大 graph-unlearning approximation gap。

需要分别回答：

1. surrogate 与 victim 的 top-k 删除选集是否仍然相似；
2. surrogate 选集施加到 victim 后，攻击效果相对 target-direct white-box reference 保留多少；
3. 上述迁移是否跨 backbone 成立，以及具有凸性和影响函数分析优势的 SGC 是否能充当 analytical surrogate。

`retrain gap` 可以继续作为 GU outcome 之一，但不单独定义 E7 的攻击目标，也不预设其必须被额外放大。

## 2. 实验组

### Group 1：GCN surrogate 跨 backbone 迁移

~~~text
GCN selector -> GAT victim + GNNDelete
GCN selector -> GIN victim + GNNDelete
~~~

该组模拟攻击者拥有可训练的 GCN surrogate，但不知道 victim 实际采用 GAT 还是 GIN。GCN selector 使用当前 OpenGU 版本化 selector 契约；proper TracIn 路径必须先通过 `proper-tracin-v1` Recipe 和 Cache V2 exact-hit gate。

### Group 2：SGC analytical surrogate 迁移

~~~text
SGC selector -> GCN victim + GNNDelete
SGC selector -> GAT victim + GNNDelete
SGC selector -> GIN victim + GNNDelete
~~~

SGC 固定图传播并使用较易分析的分类器，使 graph-aware IF/D-GIF selector 的 Hessian 求解、正则化和误差分析更清晰。执行前必须注册独立的版本化 selector Recipe；本设计将首个身份命名为 `d-gif-sgc-v1`，不得复用或改名覆盖 GCN selector Artifact。

SGC 上的凸性、Hessian 或 error-bound 结论只约束 SGC selector 自身，不构成选集迁移到 GCN/GAT/GIN 的理论保证。跨模型有效性仍由实验检验。

## 3. 明确排除的第三组

不增加 `GCN-B selector -> GCN-A victim` 的同架构、跨 checkpoint 组。该组只能隔离未知 checkpoint 带来的迁移损失，但不是当前核心 threat model，也会扩大矩阵与解释负担。

每个 victim 自己产生的 target-direct 选集仍保留为 white-box reference，但它是比较基准，不是第三个 surrogate 实验组。

## 4. 身份与公平比较合同

每个 surrogate-victim cell 必须满足：

- `selector_model_id != target_model_id`；
- selector Artifact 显式记录 model family、training identity、algorithm version、dataset/split、candidate pool、budget 和 Artifact hash；
- 同一 victim 的 surrogate 与 target-direct reference 使用相同 dataset、split、candidate pool、删除预算和 GU 配置；
- 不把 70/10/20 split 比例误写成 1%/5% 删除预算；
- target-direct 与 surrogate 只允许 selector 来源不同，不能同时改变候选池、预算或 victim checkpoint；
- random、degree 继续作为非学习型基线，并固定与目标 cell 相同的候选池和预算。

最小身份对数量为：

- Group 1：`2 victims x 5 seeds = 10`；
- Group 2：`3 victims x 5 seeds = 15`。

这是 surrogate-victim 身份对数量，不等于最终完整 cell 数；最终 YAML 还需显式展开 selector、ratio 和必要 baseline，不能用“10/15 cells”掩盖矩阵维度。

## 5. 指标与解释

### 5.1 选集迁移

- top-k Jaccard / overlap@k；
- 在共享 candidate pool 上可计算时，报告 rank correlation；
- 按 victim、ratio、seed 分层，不只报告 pooled mean。

### 5.2 攻击效果迁移

- 报告 surrogate 选集在 victim 上产生的原始 utility、loss 和现有 GU outcome；
- 与该 victim 的 target-direct white-box reference 做配对差值；
- transfer ratio 仅作描述性归一化指标，并同时报告原始分子、分母和配对差值，避免分母接近零时误读；
- 不把“retrain gap 必须比 target-direct 更大”作为通过条件。

### 5.3 结论边界

实验可以支持“选集或攻击效果在指定 backbone/GU/ratio 下迁移”，不能自动支持：

- 纯黑盒攻击；
- SGC 对非凸 victim 的理论误差保证；
- 跨未知 GU family 的泛化；
- 对未运行 backbone、dataset 或 budget 的普遍结论。

## 6. Gate 与推进关系

两组共享 Cache V2 身份与正式运行基础设施，但科学上彼此独立：

1. Group 1 由 GCN selector 的版本化 Recipe gate 解锁；
2. Group 2 由 `d-gif-sgc-v1` Recipe、SGC selector 单元验证和 Cache V2 cold/warm exact-hit gate 解锁；
3. 不再使用“前一组 transfer ratio >= 60% 才允许后一组”的单向科学门；
4. 每组完成最小 registered gate 后暂停审阅，再决定是否扩 ratio、dataset、第二个 GU family 或反向组合；
5. 本设计只修改实验契约与计划，不授权正式 GPU cell、数据准备、SSH 运行或旧 Artifact 退役。

## 8. 验收

- 所有 E7 当前入口只描述上述两个 surrogate 组；
- `GCN-B -> GCN-A` 不再出现在 E7 计划中；
- target-direct 明确标为 white-box reference，而非第三组；
- SGC 的理论保证与跨 victim 的经验迁移分开陈述；
- 不再把 approximation-gap amplification 写成 E7 的预设目标或扩展门；
- Markdown 链接检查与 dashboard generator 通过；
