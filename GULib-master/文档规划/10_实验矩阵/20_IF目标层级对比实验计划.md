## 0. 验收结论

这轮实验把三个经常混在一起的问题真正分开了：

\[
A(v)=\lVert g_v\rVert ,
\]

\[
B(v)=\lVert H^{-1}g_v\rVert ,
\]

\[
C(v;E)=\langle q_v,H^{-1}g_E\rangle .
\]

其中 \(q_v\) 可以是候选自身 \(g_v\)、原图 affected-set 梯度 \(\mathrm{grad1}_v\)，或完整删图 source \(\mathrm{grad1}_v-\mathrm{grad2}_v\)。

本地矩阵给出四个结论：

1. **B 的近似是成功的。** `b_param_hutch` 对 `b_param_lissa` 的九个数据集-seed 单元全排序 Spearman 均值为 `0.968`；k=7 时平均保留 `81.0%` 的相同候选。
2. **A 与 B 在本设置里高度相关，但不是定义等价。** A/B 全排序 Spearman 均值为 `0.962`；k 越大，集合越接近。
3. **B 与 C-GIF 不是同一个选择目标。** `b_param_lissa` 对 `gt_full` 的全排序 Spearman 只有 `0.023`，k=7 平均只重合 `17.5%`。
4. **不能只看 selection overlap。** 所有 A/B/C/控制方法都接受 k=3/7/14 的集合级删点、删边、重新训练验证，最终结论同时报告 reference fidelity 与实际删后效果。

所以 B 不是“缺一个 \(g_E\) 的错误 C”，而是合法的 target-free parameter-change 目标；它回答的是“参数会移动多远”，C 回答的是“这次移动是否沿着目标 \(E\) 的坏方向”。

## 2. 为什么 B 不需要额外 target loss

删除样本 \(v\) 后的局部参数变化写作：

\[
\Delta\theta_v \approx H^{-1}g_v .
\]

B 直接测量这个向量的大小：

\[
s_B(v)=\lVert \Delta\theta_v\rVert
=\lVert H^{-1}g_v\rVert .
\]

因此它已经有完整目标：**找出预计使参数移动最大的删除点**。只有当问题变成“这次参数移动会不会伤害某个验证/query 目标”时，才需要再投影到：

\[
g_E=\nabla_\theta L_E,
\qquad
s_C(v;E)=g_E^\top\Delta\theta_v .
\]

本轮把 B 与 C 分开实现，而不是让 B 复用 C 的 \(g_E\)。

| 配置 | B-LiSSA | B-Hutchinson |
|---|---|---|
| 定义 | \(\lVert H^{-1}g_v\rVert\) | 共享 Rademacher probes 估计同一范数 |

## 5. Selection 结果：B 是否近似成功

### 5.1 九单元全局汇总

| 对比 | k | common fraction | Jaccard | Spearman |
|---|---:|---:|---:|---:|
| A vs B-LiSSA | 3 | 0.741 | 0.656 | 0.962 |
| A vs B-LiSSA | 7 | 0.778 | 0.684 | 0.962 |
| A vs B-LiSSA | 14 | 0.881 | 0.793 | 0.962 |
| B-Hutch vs B-LiSSA | 3 | 0.704 | 0.578 | 0.968 |
| B-Hutch vs B-LiSSA | 7 | 0.810 | 0.696 | 0.968 |
| B-Hutch vs B-LiSSA | 14 | 0.841 | 0.735 | 0.968 |
| B-LiSSA vs C-GIF | 3 | 0.185 | 0.111 | 0.023 |
| B-LiSSA vs C-GIF | 7 | 0.175 | 0.104 | 0.023 |
| B-LiSSA vs C-GIF | 14 | 0.262 | 0.159 | 0.023 |

这里的全局均值覆盖 3 datasets × 3 seeds。结论是：

- A/B 高相关，说明本模型下曲率修正通常是在高梯度候选中进一步重排；
- Hutchinson 基本复现了 LiSSA 的 B 排名；
- B/C-GIF 接近不相关，证明 target projection 是目标层级上的真实分界。

### 5.2 k=7 的分数据集结果

| Dataset | A vs B common / Jaccard / Spearman | Hutch vs LiSSA common / Jaccard / Spearman | B vs C-GIF common / Jaccard / Spearman |
|---|---|---|---|
| Cora | 0.619 / 0.461 / 0.989 | 0.810 / 0.685 / 0.986 | 0.000 / 0.000 / -0.075 |
| CiteSeer | 0.714 / 0.591 / 0.920 | 0.714 / 0.569 / 0.946 | 0.190 / 0.111 / 0.012 |
| PubMed | 1.000 / 1.000 / 0.976 | 0.905 / 0.833 / 0.972 | 0.333 / 0.202 / 0.132 |

PubMed 的 A/B top-7 完全相同，不意味着两者数学等价；它只说明这个数据集、预算和三 seed 均值下，曲率修正没有跨过 top-7 边界。

## 6. 集合级下游效果配置

对每个 dataset/seed/method/k：

1. 从 `train_mask` 去掉选中节点；
2. 从图中删除所有与选中节点相连的有向边；
3. 使用相同 seed、初始化与 GCN recipe 重新训练一次；
4. 与同 seed 的未删除 base model 比较；
5. 相同 selected set 跨方法去重训练，但每个方法仍保留独立结果行。

| Primary / secondary | 指标 |
|---|---|
| Target primary | validation loss increase |
| Target secondary | validation accuracy drop |
| Utility | test loss increase、test accuracy drop |
| Training behavior | retained-train accuracy drop |
| Structural exposure | removed directed edges |
| Cost | unique selected sets、training seconds |

这个验证回答“该 selector 选出的集合删掉后，目标和 utility 实际发生什么”。它不是某个 approximate GU 算法的 approximation-gap 验证，也不是逐候选重训练。

全量覆盖：

k=7 的九单元均值：

| 方法 | Family | Validation loss increase | Paired vs random | Validation accuracy drop | Test accuracy drop |
|---|---|---:|---:|---:|---:|
| `tracin_cp_point_6` | C-point | 0.0707 | +0.0596 | 0.0404 | 0.0560 |
| `p_point` | C-point | 0.0616 | +0.0505 | 0.0331 | 0.0421 |
| `tracin_cp_graph_3` | C-GIF trajectory | 0.0602 | +0.0492 | 0.0367 | 0.0404 |
| `gt_simple` | C-IF | 0.0360 | +0.0250 | 0.0124 | 0.0164 |
| `p_graph` | C-GIF final proxy | 0.0127 | +0.0017 | 0.0082 | 0.0071 |
| `gt_full` | C-GIF reference | 0.0118 | +0.0007 | 0.0069 | 0.0082 |
| `random` | control | 0.0110 | 0.0000 | 0.0102 | 0.0096 |
| `b_param_lissa` | B | -0.0005 | -0.0116 | 0.0024 | 0.0119 |
| `b_param_hutch` | B | -0.0078 | -0.0188 | -0.0018 | 0.0059 |
| `a_grad_norm` | A | -0.0035 | -0.0145 | 0.0029 | 0.0100 |

在这个 validation-target set-deletion protocol 中：

- B-LiSSA 与 B-Hutch 都没有超过 random 的 validation-loss damage；
- k=14 时，B-LiSSA / B-Hutch 对 random 的 paired difference 进一步为 `-0.0287 / -0.0205`；
- C-point 和部分 checkpoint C 方法造成的实际 target damage 更大；
- `p_graph` 与 `gt_full` 的下游效果很接近，但二者都不是有限集合删除中的 damage 最大方法。

这不是 B 实现失败。B-Hutch 已在 selection 层复现 B-LiSSA；下游结果说明的是：**parameter displacement magnitude 在本设置中不是 validation damage 的好代理。** B 是否更能暴露某个 approximate GU 方法的 retrain gap，仍需服务器上的 algorithm-specific 实验，不能由本地结果代替。

预算趋势：

| k | Validation-loss damage 最大方法 | Mean increase | Paired vs random |
|---:|---|---:|---:|
| 3 | `tracin_cp_point_6` | 0.0218 | +0.0209 |
| 7 | `tracin_cp_point_6` | 0.0707 | +0.0596 |
| 14 | `tracin_cp_point_3` | 0.2898 | +0.2691 |

不同数据集的 k=7 winner 也不同：Cora 是 `tracin_cp_graph_3`，CiteSeer 是 `gt_simple`，PubMed 是 `tracin_cp_point_6`。因此三 seed × 三数据集支持“目标层级与近似必须分开”的结论，但不支持一个 selector 在所有设置中统一最优。

## 10. 服务器 GU follow-up 配置

本轮本地结果只验证 selector 与真实集合删除效应。若继续验证 approximate graph unlearning，建议服务器矩阵先用：

| 维度 | 冻结建议 |
|---|---|
| Datasets | Cora、CiteSeer、PubMed |
| Backbone | GCN |
| Seeds | 42、212、2024 |
| Budgets | 3、7、14 |
| GU families | GNNDelete、GraphEraser |
| 必须 selectors | random、B-LiSSA、B-Hutch、GT-full、P-graph、TracInCP-graph-6 |
| 主要指标 | approximate-vs-retrain gap、validation/query damage、test utility、prediction shift |
| Artifact reuse | selection Artifact 可复用；GU 输出必须有独立 recipe |

先跑 `GT-full / P-graph / B-LiSSA / random` 的 canary，再决定是否铺满全部 C ablation。不能把本地集合删除效果直接写成某个 GU 方法的 vulnerability。

## 11. 解释规则

| 观察 | 可以说 | 不能说 |
|---|---|---|
| Hutch 与 LiSSA 高相关 | 共享 probe 是 B 的有效 scalable proxy | Hutch 逐点数值等于 LiSSA |
| A/B 高相关 | 当前设置中曲率重排有限 | A 与 B 定义等价 |
| B/C 低相关 | 参数位移 magnitude 与目标损失投影不同 | B 实现失败 |
| C 在 validation damage 上更高 | target-aware selector 更贴近该目标 | C 必然攻击所有 GU 算法 |
| B 在某些 utility/gap 上更高 | 参数变化可能暴露另一种脆弱性 | B 比 C 更接近 eval impact |
