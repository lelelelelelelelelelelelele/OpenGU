1. 先把三条轴分开

以前把 IF / GIF / TracIn 混成一个桶，是因为同时混了三个问题。

1.1 目标轴：想选“对谁影响大”的点

层 代表分数 问的问题
A · training magnitude $\lVert g_v \rVert$ 这个点自己的训练梯度大不大
B · parameter change $\lVert H^{-1}g_v \rVert$ 删掉它后参数预计移动多远
C · target loss $\langle \mathrm{source}_v, H^{-1}g_E \rangle$ 这次参数变化是否会伤害目标集 $E$

1.2 source 轴：“删一个图节点”包含多少图变化

Source 包含什么 不包含什么
point g_v 候选节点自己的 loss gradient 邻居和删边后表示变化
simple grad1_v 原图上候选点与受影响邻域 真正删图后的邻居梯度变化
full graph q_v=grad1_v-grad2_v 原图与删后图的局部梯度差 逐候选从头重训（本轮不做）

1.3 时间轴：看最终模型，还是看训练轨迹

时间口径 代表分数 含义
single-final <source_v(theta_final), g_E(theta_final)> 只看训练结束时的对齐
TracInCP sum_c w_c <source_v(theta_c), g_E(theta_c)> 沿多个 checkpoint 累计轨迹对齐

三条轴不能互相替代。例如，point TracInCP 可能很会造成实际 damage，但它仍然不是 full-graph final GIF 的高保真近似。

2. IM 近似：没有退化为 degree

历史六数据集 concordance 在记录的 5% candidate budget 上支持：

  • IM 与 degree 的 top-k 集合重合低；
  • 在更大或更密的图上，两者更分开；
  • 因此 IM 保留了独立的 coverage / diffusion 信号。

安全说法是：

历史 IM 没有在 set level 退化为 degree；但这不证明它优化的 independent spread 更高，更不证明 attack outcome 更强。

新 A.7 不再做 public split 的固定小 $k$ bridge，而直接使用 canonical OpenGU train candidates：

轴 新实验合同
Datasets Cora / CiteSeer / PubMed canonical transductive 80/0/20
Ratios 1% / 5% of complete train candidates
Expected $k$ Cora 21/108；CiteSeer 26/133；PubMed 157/788
Primary comparison mature IM vs degree；random 为负控制
Outputs cold/warm、RSS、保证/证书、score 形态、Jaccard、independent spread + paired CI
GU boundary 只有 spread gate winner 才可另行报备 5% GU canary

正式 candidate count 与 $k$ 仍必须由 SSH canonical manifest 实测并冻结。Jaccard 只解释选点差异；“超过 degree”必须由 selector-independent spread 证明，GU 攻击优势必须再由 retrain gap 证明。

3.2 17-output GPU cold/warm 实测（2026-07-21）

本轮把 b_param_lissa 明确留在历史 numerical-validation 边界，正式 ScoreBundle 固定为其余 17 个 score/ranking 输出。RTX 4090 上完成 3 datasets × 3 seeds = 9 cells：

  • 9/9 cells 成功，153/153 方法级 cold Selection Artifact 为 miss_saved，warm 全部 exact hit，失败数为 0；
  • ScoreBundle cold total mean/max 为 6.8038 / 9.1624 s；warm exact read mean/max 为 0.3200 / 0.9635 s；
  • 峰值显存最大 allocated/reserved 为 357.0 / 384.0 MiB；
  • 方法级时间包含逐 Artifact 索引、完整性校验与共享文件系统访问，故 warm hit 的验收含义是“零 producer、身份精确命中”，不是承诺每次 wall-clock 必然短于 cold。

这组数据关闭的是“历史 public-split 17-output ScoreBundle 的 cold/warm、显存与失败状态”证据缺口；它不等同于 canonical OpenGU selector benchmark 或 GU canary，也不自动关闭 Hybrid 或 C.6 transfer gate。逐 cell 与逐方法数字见上述双格式报告。

3.3 fidelity 与实际 damage 是两个轴

p_graph 与 gt_full 的实际集合删除效果也很接近，说明它的 reference fidelity 确实传递到了选中集合。但在 k=7 时：

  • tracin_cp_point_6 的平均 validation-loss increase 是 0.0707；
  • gt_full 只有 0.0118。

因此：

“最像 final GIF”与“对有限 top-k 集合造成最大实际伤害”必须分开报告。

7. SUP 和论文可以怎么讲

论文分工固定为：Appendix A.6 负责 A/B–C–D taxonomy 与组内/组间 concordance，Appendix A.7 负责现代 IM 的时间/保证/score/degree comparison 与 trajectory influence 的 target-direct validity。本页继续作为 production/attack 状态入口，不把 selector fidelity 写成 GU outcome。

可以讲：

  1. 历史 IM 保留了不同于 degree 的 coverage 信号；现代 IM 是否超过 degree 仍待 canonical 1%/5% 实验。
  2. A/B/C 是不同影响目标；A/B 在当前矩阵里高相关，不代表定义等价。
  3. B-Hutchinson 是 B-LiSSA 的可扩展近似；p_graph 是当前 full-GIF reference 的最强 Hessian-free proxy。
  4. source fidelity 和实际 set-deletion damage 是两个评估轴。
  5. proper TracIn 已具备可审计的 Score → Selection 身份，但尚未完成 approximate-GU canary。

不能讲：

  • single-final <g_v,g_E> 就是标准 TracInCP；
  • point IF 或 simple IF 就是 full graph GIF；
  • checkpoint 越多就一定更好；
  • 旧 TracIn 结果已证明 influence-based attack 弱于 degree；
  • selection fidelity 高就必然实际 damage 最大。
