# 策略输出重合度实验：结构轴与 A/B–C–D influence 轴

这页是 Obsidian 规划与论文 supplementary 的共同桥梁：统一回答不同 selector 是否选中相同节点，并明确区分组内近似验证和组间机制比较。

方法定义见 [[20_研究框架/20_方法与策略框架]]；完整 IF/GIF 配置与结果见 [[20_IF目标层级对比实验计划]] 和 [[21_C目标TracIn与GIF近似有效性实验计划]]。本页对应论文 A.6；IM coverage 与 trajectory influence 的 proxy validity 独立进入 [[12_近似策略重合度实验]] / Appendix A.7。

## 1. 比较框架

| 层级 | 方法 | 要回答的问题 |
|---|---|---|
| 结构控制 | degree、PageRank、IM | 结构 selector 是否复用相同中心性信号 |
| A/B 参数变化组 | A=$\lVert g_v\rVert$；B=$\lVert H^{-1}g_v\rVert$ | Hessian-free 梯度量是否能代理参数位移排序 |
| C-IF 组 | point/simple IF 及其 Hessian-free、checkpoint 版本 | 不含 `grad2` 时，同 source 近似是否稳定 |
| D-GIF 组 | `grad1-grad2` 的 full GIF 及其代理 | graph-deletion source 下近似是否复现 GIF reference |
| 组间 | A/B vs C；A/B vs D；C vs D | 不同机制是否实际选择不同节点 |

旧 cross-TracIn 和 topology selector 是外部控制，不属于 D；D 只指包含 `grad1-grad2` 的 graph-aware GIF 路线。

## 2. 指标与边界

top-k 集合使用：

```text
Jaccard(S_a, S_b) = |S_a ∩ S_b| / |S_a ∪ S_b|
common@k = |S_a ∩ S_b| / k
```

完整排序使用 Spearman。Overlap 只能说明选择行为是否一致，不能替代集合级删除后的真实 outcome；因此每个 influence selector 还要接 k=3/7/14 的删点、删边与同 recipe 重训练验证。

## 3. 组内近似验证

下表均为 Cora、CiteSeer、PubMed × seeds 42/212/2024 的描述性均值。

| 组 | 比较 | 全排序 Spearman | k=7 common | 结论 |
|---|---|---:|---:|---|
| A/B | A vs B reference | 0.962 | 0.778 | A 是 B 排序的强 Hessian-free 代理；不是定义等价 |
| C-point | `p_point` vs `r_point` | 0.969 | 0.889 | 同 source 去 Hessian 后仍高度一致 |
| C-simple | `p_simple` vs `gt_simple` | 0.958 | 0.921 | no-grad2 IF 的 final proxy 有效 |
| D-GIF | `p_graph` vs `gt_full` | 0.984 | 0.905 | D 内 single-final graph proxy 最接近 reference |
| D trajectory | `tracin_cp_graph_3/6` vs `gt_full` | 0.498 / 0.529 | 0.349 / 0.365 | checkpoint 累积没有自动逼近 final GIF |

所有 reference 中的 $H^{-1}g$ 统一通过迭代 IHVP 求解。solver、HVP 和 shared-probe 配置只作实现 sanity check，不进入 selector 组内/组间矩阵。

## 4. 组间机制比较

| 比较 | Spearman | k=7 common | 解释 |
|---|---:|---:|---|
| C-simple IF vs D-full GIF：`gt_simple` vs `gt_full` | 0.040 | 0.111 | `grad2` 不是小修正；C 与 D 是不同机制 |
| C-point IF vs D-full GIF：`r_point` vs `gt_full` | 0.112 | 0.190 | candidate-only IF 不能当作 graph-aware GIF |
| B reference vs D-full GIF | 0.023 | 0.175 | 参数位移大小与 graph-aware eval impact 不是同一排序 |

完整的 A/B vs C 交叉矩阵仍应作为下一轮汇总项补齐；当前已有 C-point/C-simple 与 D 的直接证据，以及 B 与 D 的强分离证据。组间结果不应被误写为某组“实现失败”。

## 5. 结构 selector 锚点

| 问题 | 当前结果 | 解释 |
|---|---|---|
| degree 和 PageRank 是否相近 | 较高重合，但数据集相关 | 都是结构中心性，但不能互换 |
| IM 是否退化成 degree | 没有；多数据集集合重合较低 | IM 的组合覆盖不同于单点中心性 |
| legacy cross-TracIn 是否只是结构 selector | 与 degree / IM 近乎正交 | 它是外部 model-based 控制，但算法口径已标为 legacy |

## 6. 快跑迭代策略

不等待“所有内容一次做完”，而按最小闭环滚动：

1. 每增加一个 reference/proxy pair，先完成组内 Spearman + Jaccard@k；
2. 再补它与相邻机制组的交叉比较；
3. 通过 selection gate 后，才运行集合级删后重训练；
4. Obsidian 本页当天回填结论与证据链接；
5. 同一小批次同步进入 SUP 草稿，标注 `descriptive`、`pending` 或 `accepted`。

这样 OB 是实验与论文的接口，而不是等全部实验结束后才补写的总结。

## 7. 不能推出的结论

- 高重合不等于两个定义相同；
- 低重合不等于其中一个实现失败；
- IHVP solver 变体的一致性不构成新的 selector 结论；
- selection fidelity 不等于有限集合 damage 最大；
- 本地 set-deletion 结果不等于某个 approximate GU 方法的 end-to-end vulnerability。
