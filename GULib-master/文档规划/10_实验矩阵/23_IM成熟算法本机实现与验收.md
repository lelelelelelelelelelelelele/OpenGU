## 1. 实现范围

### 1.1 核心图与 RR 层

| 文件 | 作用 | 关键合同 |
|---|---|---|
| `rr_core.py` | directed IC reverse-reachable sampling、压缩 candidate incidence、coverage/inverted index | 不自动无向化；候选域显式；seed 可复现 |
| `contracts.py` | `ScoreArtifact`、`SelectionArtifact`、`ApproximationCertificate` | 完整向量、只读 ndarray、有限值、JSON 可序列化 |
| `exact_tiny.py` | 最多 20 条边的 live-edge 精确枚举 | 为 score/selection 提供小图真值 |

### 1.2 全量 Score 层

| 输出 | Score 形式 | Budget | 可以叠加吗 | 不应声称 |
|---|---|---:|---|---|
| RR-SNI | 每个候选的 singleton spread 估计 | 无关 | 可以；语义固定后可和其他静态分数归一化后融合 | top-$k$ 有 IM 近似保证 |
| RR-Shapley | candidate game 中的平均边际贡献 | 无关 | 可以；比 SNI 更显式考虑 coalition attribution | top-$k$ 等价 set-level greedy |
| RR-$k$-semivalue | coalition size 固定为 $k-1$ 时的期望边际 | 相关 | 可以，但 recipe 必须带 $k$ | 一个向量跨预算复用 |
| accepted marginal trace | selector 选中节点当时的 residual gain | 相关且路径相关 | 不作为未选节点的全量静态分数 | Stage 1 full score |

这回答了原问题：IM 的 set-level optimum 本身没有一个天然、预算无关的全量静态 score；但可以从同一 RR bundle 产出三种语义明确的完整 score，专门承担 Stage 1 / score fusion，再把 IMM/OPIM-C 保留为联合 selection 线。两条线在正式实验中竞争，不能提前假设 static top-$k$ 等于 joint IM。

### 1.3 Selector 与理论标签

| 方法 | 本实现输出 | 当前标签 |
|---|---|---|
| RR maximum coverage greedy | ordered selection、accepted gains、coverage trace | 固定 RR hypergraph 上的 deterministic greedy |
| corrected IMM | independent pilot/final RR、selection、$1-1/e-\epsilon$ target metadata | `paper_equivalent=false`；Chen workaround 1 结构已落实，candidate-restricted theory 尚待正式 audit |
| OPIM-C-shaped | 独立 selection/validation RR、逐轮 lower/upper/ratio certificate | `paper_equivalent=false`；当前为 conservative union-Hoeffding v1，不冒充论文 tight bound |

其中“有 certificate”与“论文实现等价”是两件事。机器 artifact 中保留 `kind`、`failure_probability`、`paper_equivalent` 和 details；报告不得只显示一个近似比而隐藏适用范围。

## 2. Benchmark 与时间口径

统一 runner 支持 9 个小图方法：

```text
degree / random
im_batch_celf_current / im_celf_strict
rr_sni / rr_shapley / rr_ksemivalue
corrected_imm / opimc
```

每个 budget 强制生成 degree 参照，并用**与 selector 独立**的 RR batches 对所有 selection 做 paired evaluation。静态 RR score 的时间不只记 top-$k$：

$$
T_{\mathrm{end-to-end}}
=T_{\mathrm{RR\ sample}}
+T_{\mathrm{reducers}}
+T_{\mathrm{top-k}}.
$$

artifact 同时保留：

- `online_wall_seconds`；
- `shared_precompute_wall_seconds`；
- `wall_seconds`（保守 end-to-end）；
- `excluded_one_time_setup_wall_seconds`；
- peak RSS 与 Python allocation peak。

旧 Numba-CELF 先执行一次注册的 2-node warmup，warmup 单独记录，不把约 3 秒 JIT 成本随机算到先运行的 current 或 strict 方法头上。正式报告仍应同时展示 setup 与 steady selector time。

## 4. Runner 安全边界

`run_planetoid.py` 与 `run_arxiv.py` 默认只做 preflight；真正执行必须同时给出 `--execute --approval-token IM-SELECTOR-A`。`--formal` 还要求：

- 当前分支严格为 `main`；
- worktree clean；
- 数据解析到 active checkout 内的 canonical path；
- output 显式给定且默认拒绝覆盖。

当前 `registered_plan.json` 固定 `formal_execution_authorized=false`。本轮没有调用上述执行入口；正式 SSH 矩阵继续受 [[22_IM成熟算法可用性与Degree超越实验计划]] 的审批与 Git 规则约束。

## 5. 明日验收建议

按下面顺序检查即可：

1. 看 `ScoreArtifact` 是否真的覆盖完整候选域，以及三种 semantics 是否满足后续融合需求；
2. 看 corrected IMM 的 final RR batch 是否与 pilot seed/batch 独立；
3. 看 OPIM-C-shaped artifact 的 `paper_equivalent=false` 是否在代码、JSON、报告三处一致；
4. 看静态 score 时间是否包含 RR generation/reducer，旧 CELF JIT 是否单列；
5. 跑 25 项定向测试与 `local_smoke`；
6. 决定实现线是接受、要求修订，还是暂不进入 `main`；
7. 只有接受后，再审批 Phase S 的首个 canonical dataset/seed/1% gate，不能直接铺满 126/36 rows。

## 6. 已知缺口

- 未在 Obsidian reading view 视觉验收；当前环境未发现 Obsidian 可执行程序。静态 HTML 会另做浏览器截图检查。
- 本机 RTX 5070 为 `sm_120`，当前 PyTorch wheel 只支持到 `sm_90`；涉及旧 Hybrid/TracIn 的本机回归需显式 `CUDA_VISIBLE_DEVICES=-1`，本次 CPU 回归为 85/85 通过。
- OPIM-C tight paper certificate 尚未复现；当前 adapter 是保守、可审计的独立双样本版本。
- candidate-restricted IMM/OPIM 理论适配尚未完成独立 proof audit，因此均不标 `paper_equivalent=true`。
- 尚无 Planetoid/ogbn-arxiv runtime、RSS、spread 或 degree win 结果。
- `run_planetoid.py` 已明确为 public-split 诊断入口并拒绝 `--formal`；`registered_plan.json` 与 canonical processed runner 的默认 ratio 已改为 1%/5%。正式执行前仍需验收三数据集 orchestration、逐数据集 canonical preflight 与输出 identity。
- 尚未接入正式 Cache V2；当前为隔离的 experiment artifact lane，避免污染 production AttackManager。

## 7. 一句话记忆

> IM 的 joint selection 不能硬压成一个天然静态分数；现在已经有三种可叠加、可全量物化的 RR score，以及两种保留集合冗余语义的 selector。实现和玩具图合同已过，但是否快、是否有足够强的可审计保证、是否超过 degree，必须等用户批准后的正式小图/大图矩阵。
