## 4090 角色

| 机器 | 角色 | 适合跑 |
|---|---|---|
| RTX 4090 24GB | 小数据集主力 | Cora GCN/GAT 主矩阵、ratio sweep、Citeseer、GIN、alpha sweep |
| >=80GB GPU | 大图 / arxiv 主力 | arxiv TracIn / Hybrid / collateral retrain |

4090 的正确用法是把小数据集矩阵尽量跑全、打包回本地分析；不要把 arxiv 主矩阵塞进这条线里。

GraphRevoker repair 后的 `sanity_graphrevoker.yaml`、`sanity_graphrevoker_r05_full.yaml` 以及后续 Cora/Citeseer 小图 rerun，都归 4090 小数据集线。本地 RTX 5070 环境只用于 coding / dry-run / CPU 调试，不参与正式 GPU 证据链。

## 不重跑规则

不要用“新开机器”当重跑理由。只有下面几类才重跑：

| 条件 | 动作 |
|---|---|
| 服务器侧四件产物齐：`attack.json` / `collateral.json` / `predictions.npz` / `_meta.json`，且 `attack.json` 内无 `failed=true` | 不重跑，允许 ship 回本地 |
| 本地 `results/runs/4090/...` 中 `attack.json` / `collateral.json` / `_meta.json` 齐 | 直接纳入本地分析；缺 `predictions.npz` 是预期状态，不触发传输或重跑 |
| 服务器侧只有 `attack.json`，缺 collateral / predictions / meta | 只补 collateral / predictions / meta；不要重跑 attack |
| `attack.json` 内有 `failed=true` | 按失败原因定位，必要时清对应 method state 后重跑该 cell |
| method 实现变动，例如 GraphRevoker dispatcher / aggregator 修复 | 只重跑受影响 method |
| selector 定义变动，例如 TracIn 公式修复 | 只重跑 `tracin` 和依赖它的 `hybrid` |
| aggregate CSV 没覆盖新结果 | 重建 aggregate，不重跑实验 |

## 回收与分析

服务器侧先 gate，再 ship：

```bash
bash scripts/ship_results.sh cora
```

本地只做分析和汇总，不在本地补跑 GPU 实验。打包策略优先只带 `*.json` 和 `_meta.json`，`predictions.npz` 是服务器 gate 的完整性检查物，不是本地分析必需输入。

本地分析顺序：

```powershell
E:/conda_package/envs/gnn/python.exe scripts/aggregate_phase_b.py 4090
E:/conda_package/envs/gnn/python.exe scripts/plot_phase_b_cora.py
E:/conda_package/envs/gnn/python.exe scripts/build_paper_table1.py
```

如果 aggregate 仍然只有 360 行，说明只汇了 B.3/B.4 主矩阵；A.5/A.6/A.3 需要单独纳入或单独出表，不要误读成“远端没结果”。
