# 方法与策略框架

这页放定义。实验页不要再承担方法介绍，否则层级会乱。

TracIn / proper TracIn / GIF / self-influence 的公式边界单独见 [[21_TracIn变体与GIF关系]]；本页只保留总框架。

---

## 1. 两类对象别混

| 对象 | 是什么 | 例子 |
|---|---|---|
| GU method | 执行 graph unlearning 的算法 | GIF / GNNDelete / MEGU / IDEA / GraphEraser / GraphRevoker |
| deletion selector | 决定删除哪些节点的策略 | random / degree / pagerank / IM / TracIn / Hybrid |

实验矩阵是二者交叉：**某个 selector 选择 deletion request，然后某个 GU method 执行 unlearning**。

---

## 2. Selector 的层级

| selector | 类型 | 直觉 | 框架角色 |
|---|---|---|---|
| random | naive baseline | 不带结构和模型信息 | 预算匹配的噪声底线 |
| degree | naive structural | 删除高度数节点，打结构 volume | 最强也最危险的低权限 baseline |
| pagerank | naive structural | 删除全局中心节点 | degree 的全局中心性版本 |
| IM | approximate topology / propagation | 近似最大化传播覆盖 | 检查 coverage signal 是否不同于中心性 |
| TracIn | approximate IF / model-based | 用梯度相似近似 influence | 检查 model sensitivity signal |
| Hybrid | fused approximation | 融合 IM 与 IF proxy | 检查 coverage + sensitivity 是否互补 |
| GIF | expensive IF reference | 用 `H^-1 grad L_E` 近似真实 graph IF | 小图上校准 IF proxy |

这里的 naive 不是贬义。degree / pagerank 是必须正面面对的强 baseline；如果它们强，说明结构 volume 本身就是重要发现。

---

## 3. 为什么说 IM 和 IF 都是近似策略

IM 和 IF 都不是“真实攻击效果”的直接读数。它们都是用某个代理目标来挑节点：

| 近似策略 | 代理目标 | 近似什么 | 风险 |
|---|---|---|---|
| IM | propagation / coverage | 删除节点对图上传播覆盖的影响 | 覆盖大不等于 unlearning 近似误差大 |
| IF / TracIn | model-impact 或 loss sensitivity | 删除训练点对模型参数、模型状态或 held-out/query loss 的影响 | 必须先说清楚“影响谁” |
| Hybrid | coverage + sensitivity | 两条代理信号的组合 | 若 IF 分支不干净，融合也不干净 |

### 3.1 IM 是哪一种近似

当前代码里的 `im` 是 **Independent Cascade (IC) spread + Monte Carlo + CELF greedy**：

| 组件 | 当前含义 |
|---|---|
| diffusion model | Independent Cascade，边传播概率默认 `propagation_prob=0.1` |
| spread estimate | Monte Carlo 模拟，默认 `mc_rounds=100`；arxiv 配置常用 `50` |
| greedy optimizer | CELF lazy greedy；小图默认 batch-CELF，加速但仍是近似 |
| candidate pruning | 小图默认全 train candidates；arxiv 常用 `candidate_fraction=0.1` 做 top-degree 裁剪 |
| selector seed | `im_selector_seed=2024`，与 GU training seed 解耦 |

所以 IM 的结论边界是：它近似的是 **propagation / coverage**，不是直接近似 GU damage，也不是直接近似 held-out loss influence。

### 3.2 IF selector 先要定义“影响谁”

IF / GIF 的 model editing 直觉是成立的：给定一个要删除的数据点或数据集 `D`，它估计的是删除 `D` 后模型参数怎么变：

```text
Delta theta_D ~= - H_train^-1 grad L_D
```

这本身不需要 test set。问题出在把它变成 selector 时，必须给“影响大”一个可排序的分数。这里不是两组，而至少要拆成三类目标：

| selector 目标 | 典型分数 | 问的问题 |
|---|---|---|
| training-objective / model-state magnitude | `||g_v||` 或 leverage proxy | 这个点自身的训练 loss 梯度 / 局部模型状态是否尖锐 |
| parameter-change IF | `||H_train^-1 g_v||` | 删除这个点会不会造成大的参数扰动 |
| eval / generalization impact IF | `<grad L_E, H_train^-1 g_v>` | 删除这个点会不会影响 held-out/query loss |
| GU-update alignment | 与某个 unlearning update direction 对齐 | 这个点是否触发类似某个 GU method 的局部更新方向 |

所以不能把 “IF selector” 自动等同于 test-set influence。eval-impact 是一种清楚的 IF 目标，但不是唯一目标。若论文主张“选择对模型编辑/参数状态影响大的点”，parameter-change IF 更贴近原始意图；若论文主张“训练目标/模型状态敏感点”，`||g_v||` 这类 magnitude proxy 又应该单独列出。

2026-07-10 的 first-pass 诊断已把三类目标拆开：training-objective magnitude 与 parameter-change IF 在该 Cora/GCN 设置下选集接近，但概念上仍是两类；eval/generalization impact 则是另一条目标轴。deployed cross-TracIn 不算第四个干净目标，只作为 legacy selector / 反例保留。这里是定义页，不承载实验数字；数值、完整复现命令和证据边界统一见 [[10_实验矩阵/12_近似策略重合度实验]]，公式解释见 [[21_TracIn变体与GIF关系]]。

### 3.3 TracIn / proper-TracIn / GIF 的公式边界

详细学习页见 [[21_TracIn变体与GIF关系]]。这里保留最小定义，避免实验页反复复制。

设候选节点梯度为 `g_v = grad loss_v`，`E` 是 held-out evaluation/query set，不是 deletion candidate pool。

| 名称 | 分数形式 | 实际含义 |
|---|---|---|
| deployed cross-TracIn | `<g_v, -sum_j grad loss_j>` | 与训练梯度残差 / 正则方向对齐 |
| eval-impact proper TracIn | `<g_v, grad L_E>` | Hessian-free held-out/query loss sensitivity |
| eval-impact GIF / real IF | `<g_v, H^-1 grad L_E>` | 曲率预条件后的 evaluation-loss sensitivity |

当前旧 TracIn 结果的问题是：deployed cross-TracIn 使用了训练梯度残差方向。它不是干净的 eval-impact IF，也不是干净的 model-impact norm；更像 training-residual alignment。Hybrid 复用 TracIn 分支，因此 TracIn 公式变化也影响 Hybrid。
