# 方法与策略框架

这页放定义。实验页不要再承担方法介绍，否则层级会乱。

TracIn / proper TracIn / GIF / self-influence 的公式边界单独见 [[21_TracIn变体与GIF关系]]；本页只保留总框架。

---

## 1. 两类对象别混

| 对象 | 是什么 | 例子 |
|---|---|---|
| GU method | 执行 graph unlearning 的算法 | GIF / GNNDelete / MEGU / IDEA / GraphEraser / GraphRevoker |
| deletion selector | 决定删除哪些节点的策略 | random / degree / pagerank / IM / TracIn / Hybrid |

实验矩阵是二者交叉：**某个 selector 选择 deletion request，然后某个 GU method 执行 unlearning**。

---

## 2. Selector 的层级

| selector | 类型 | 直觉 | 框架角色 |
|---|---|---|---|
| random | naive baseline | 不带结构和模型信息 | 预算匹配的噪声底线 |
| degree | naive structural | 删除高度数节点，打结构 volume | 最强也最危险的低权限 baseline |
| pagerank | naive structural | 删除全局中心节点 | degree 的全局中心性版本 |
| IM | approximate topology / propagation | 近似最大化传播覆盖 | 检查 coverage signal 是否不同于中心性 |
| TracIn | approximate IF / model-based | 用梯度相似近似 influence | 检查 model sensitivity signal |
| Hybrid | fused approximation | 融合 IM 与 IF proxy | 检查 coverage + sensitivity 是否互补 |
| GIF | expensive IF reference | 用 `H^-1 grad L_E` 近似真实 graph IF | 小图上校准 IF proxy |

这里的 naive 不是贬义。degree / pagerank 是必须正面面对的强 baseline；如果它们强，说明结构 volume 本身就是重要发现。

---

## 3. 为什么说 IM 和 IF 都是近似策略

IM 和 IF 都不是“真实攻击效果”的直接读数。它们都是用某个代理目标来挑节点：

| 近似策略 | 代理目标 | 近似什么 | 风险 |
|---|---|---|---|
| IM | propagation / coverage | 删除节点对图上传播覆盖的影响 | 覆盖大不等于 unlearning 近似误差大 |
| IF / TracIn | model-impact 或 loss sensitivity | 删除训练点对模型参数、模型状态或 held-out/query loss 的影响 | 必须先说清楚“影响谁” |
| Hybrid | coverage + sensitivity | 两条代理信号的组合 | 若 IF 分支不干净，融合也不干净 |

### 3.1 IM 是哪一种近似

当前代码里的 `im` 是 **Independent Cascade (IC) spread + Monte Carlo + CELF greedy**：

| 组件 | 当前含义 |
|---|---|
| diffusion model | Independent Cascade，边传播概率默认 `propagation_prob=0.1` |
| spread estimate | Monte Carlo 模拟，默认 `mc_rounds=100`；arxiv 配置常用 `50` |
| greedy optimizer | CELF lazy greedy；小图默认 batch-CELF，加速但仍是近似 |
| candidate pruning | 小图默认全 train candidates；arxiv 常用 `candidate_fraction=0.1` 做 top-degree 裁剪 |
| selector seed | `im_selector_seed=2024`，与 GU training seed 解耦 |

所以 IM 的结论边界是：它近似的是 **propagation / coverage**，不是直接近似 GU damage，也不是直接近似 held-out loss influence。

### 3.2 IF selector 先要定义“影响谁”

IF / GIF 的 model-editing 直觉是成立的：给定候选删除点 \(v\)，先由训练 loss 定义：

\[
g_v=\nabla_\theta \ell_v(\theta^*),
\qquad
H=\nabla_\theta^2 L_{\mathrm{train}}(\theta^*),
\qquad
\Delta\theta_v\approx H^{-1}g_v .
\]

符号正负取决于把“删除”写成 downweight 还是把“加权”写成 upweight；做同一口径的排序时，关键是方向与绝对值约定一致。\(H^{-1}\) 也不需要显式存储，实际只求 inverse-Hessian-vector product。

从“参数会怎么变”变成 selector 时，必须再定义“影响大”到底指什么。**A/B/C 就是本项目的第一层目标分区：**

| 分区 | 正式目标 | 需要 \(E\) 吗 | 需要 \(H^{-1}\) 吗 | “影响谁” |
|---|---|---:|---:|---|
| **A. training-gradient magnitude** | \(A(v)=\lVert g_v\rVert\) | 否 | 否 | 候选点自身的训练-loss 梯度有多大 |
| **B. parameter-change IF** | \(B(v)=\lVert H^{-1}g_v\rVert\) | 否 | 是 | 删除候选点预计让模型参数移动多远 |
| **C. eval-impact IF** | \(C(v;E)=g_E^\top H^{-1}q_v=\langle q_v,H^{-1}g_E\rangle\) | 是 | reference 需要 | 这次参数变化会让指定目标 \(E\) 的 loss 改变多少 |

其中：

- A 是“进入曲率修正之前”的 magnitude control，严格说不是完整 influence function；
- B 是完整而且 **target-free** 的 parameter-change IF，并不是“漏掉 \(g_E\) 的 C”；
- C 才需要 \(g_E=\nabla_\theta L_E\)，因为它要把参数位移投影到指定 evaluation/query loss 上；
- 若 \(H\) 对称，\(g_E^\top H^{-1}q_v\) 与 \(\langle q_v,H^{-1}g_E\rangle\) 等价，因此可以先共享计算一次 \(H^{-1}g_E\)。

可以把三者记成一条逐步增加问题约束的链：

```text
A: 候选梯度有多大
        ↓ 加入训练曲率
B: 参数会移动多远
        ↓ 再指定 evaluation/query 目标 E
C: 这次移动会让 E 的 loss 改变多少
```

#### C 内部还要单独区分 graph source

C 的“影响谁”固定为 \(E\)，但删除操作的 source \(q_v\) 仍有三种层级：

| C 子类 | source \(q_v\) | reference score | graph-aware 含义 |
|---|---|---|---|
| **C-point** | \(g_v\) | \(\langle g_v,H^{-1}g_E\rangle\) | 只看候选节点自己的 loss 梯度 |
| **C-IF / simple** | \(\mathrm{grad1}_v\) | \(\langle \mathrm{grad1}_v,H^{-1}g_E\rangle\) | 加入原图 affected neighbors，但不计算删后图变化 |
| **C-GIF / full** | \(\mathrm{grad1}_v-\mathrm{grad2}_v\) | \(\langle \mathrm{grad1}_v-\mathrm{grad2}_v,H^{-1}g_E\rangle\) | 再加入删除边后邻居梯度的变化 |

\(\mathrm{grad2}_v\) 是在同一参数 \(\theta^*\) 上，对删边后的图做一次 forward/backward；它不要求为每个候选点重新训练模型。因此 **A/B/C 是目标分区，point/simple/full 是 C 的 source 分区**，两者不能混成一维。

#### 近似方法是第三条独立轴

在固定 C 子类后，才比较计算近似：

| 近似轴 | 形式 | 改变了什么 |
|---|---|---|
| IF/GIF reference | \(\langle q_v,H^{-1}g_E\rangle\) | 保留 final-point 曲率修正 |
| single-final Hessian-free | \(\langle q_v,g_E\rangle\) | 只移除 \(H^{-1}\)，source 与 \(E\) 不变 |
| multi-checkpoint TracIn | \(\sum_c w_c\langle q_v(\theta_c),g_E(\theta_c)\rangle\) | 移除 \(H^{-1}\)，并累计训练轨迹 |

所以 TracIn 不是 A/B/C 之外的“D 类”。当它使用 \(g_E\) 时，它是 **C 目标的 Hessian-free / trajectory approximation**。旧 deployed cross-TracIn 使用 training-gradient residual 而不是 \(g_E\)，不属于干净的 C，只保留为 legacy negative control。正式 selector 应使用 validation/query set 定义 \(E\)；test split 只可用于明确标注的机制诊断，不能在正式攻击选点中泄漏标签。

- [[10_实验矩阵/21_C目标TracIn与GIF近似有效性实验计划|C 的 point/simple/full、Hessian-free 与 checkpoint 矩阵]]；

当前本地矩阵支持这个分层：B-Hutch 对 B-LiSSA 的全排序 Spearman 为 `0.968`，而 B-LiSSA 对 C-GIF 仅 `0.023`；固定 full-graph source 后，`p_graph` 对 `gt_full` 为 `0.984`。前两个数字验证 B/C 是不同目标，第三个数字验证“固定目标与 source 后再讨论 Hessian 近似”才是可解释的比较。

### 3.3 IF / GIF / TracIn 在 A/B/C 中的位置

详细学习页见 [[21_TracIn变体与GIF关系]]。这里保留最小定义，避免实验页反复复制。

| 名称 | A/B/C 位置 | 分数形式 | 实际含义 |
|---|---|---|---|
| gradient norm | A | \(\lVert g_v\rVert\) | training-gradient magnitude control |
| parameter-change IF | B | \(\lVert H^{-1}g_v\rVert\) | target-free 参数位移 |
| point IF | C-point | \(\langle g_v,H^{-1}g_E\rangle\) | 候选自身对 \(E\) 的 final-point influence |
| graph-aware GIF | C-GIF | \(\langle \mathrm{grad1}-\mathrm{grad2},H^{-1}g_E\rangle\) | 完整图删除 source 对 \(E\) 的 influence |
| single-final eval proxy | C 的近似 | \(\langle q_v,g_E\rangle\) | 固定 source，去掉 Hessian |
| multi-checkpoint TracIn | C 的近似 | \(\sum_c w_c\langle q_v(\theta_c),g_E(\theta_c)\rangle\) | 固定 C 目标，累计训练轨迹 |
| deployed cross-TracIn | legacy / 不归入干净 A/B/C | \(\langle g_v,-\sum_{j\in T}g_j\rangle\) | training-gradient residual alignment |

Hybrid 若复用 TracIn 分支，其语义也随该分支改变：legacy 分支只能称 legacy Hybrid；使用 \(g_E\) 后，才可以解释成 coverage 与 C-target sensitivity 的融合。

## 4. 和 supplementary 实验页的关系

supplementary overlap / validity 需要分三部分：

1. **目标层级差异**：A、B、C 是否确实给出不同排序？
2. **同目标近似有效性**：固定 B 或固定 C 的 source 后，proxy 是否复现 reference？
3. **集合级下游效果**：top-k 集合删掉并重训练后，validation target 与 test utility 实际如何变化？
