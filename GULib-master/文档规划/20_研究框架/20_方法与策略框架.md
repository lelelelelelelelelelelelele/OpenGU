# 方法与策略框架

这页只放定义。实验页不再重复承担方法介绍。

TracIn / proper TracIn / GIF / self-influence 的公式边界见 [[21_TracIn变体与GIF关系]]。

## 1. 两类对象别混

> [!info] GU method · 谁来执行遗忘
> Graph Unlearning 算法接收 deletion request，并真正执行 unlearning。
>
> **例子：** GIF、GNNDelete、MEGU、IDEA、GraphEraser、GraphRevoker。

> [!example] Deletion selector · 删除谁
> Selector 只负责决定哪些节点进入 deletion request。
>
> **例子：** random、degree、PageRank、IM、TracIn、Hybrid。

> [!summary] 实验矩阵
> **selector 选择删除对象 × GU method 执行 unlearning。**
>
> 两条轴必须分开，不能把 selector 的效果直接写成某个 GU method 的定义。

## 2. Selector 的层级

| 层级 | Selector | 选择信号 | 在框架中的作用 |
|---|---|---|---|
| 无信息基线 | **random** | 不使用结构或模型信息 | 预算匹配的噪声底线 |
| 结构基线 | **degree** | 节点度数 / structure volume | 最强也最危险的低权限 baseline |
| 结构基线 | **PageRank** | 全局中心性 | degree 的全局版本 |
| 传播覆盖 | **IM** | Independent Cascade coverage | 检查 coverage 是否不同于中心性 |
| 模型敏感性 | **TracIn** | 依 source 定义的 Hessian-free / trajectory score | 检查 sensitivity；名称必须绑定 source 与公式 |
| 图感知影响 | **GIF reference** | `grad1-grad2` 与 $H^{-1}g_E$ | 在小图上校准 D-GIF proxy |
| 融合 | **Hybrid** | coverage + influence sensitivity | 检查两类信号是否互补 |

> [!warning] Naive 不等于弱
> degree / PageRank 是必须正面面对的强 baseline。它们如果获胜，说明结构 volume 本身就是重要机制发现。

> [!note] 命名边界
> “TracIn” 必须绑定 source 与公式；Hybrid 也必须注明使用 legacy、C-IF 还是 D-GIF influence 分支。

## 3. 为什么 IM、IF 和 Hybrid 都是代理策略

它们都不是“真实攻击效果”的直接读数，而是用某个代理目标选择节点。

| 近似策略 | 代理目标 | 主要解释风险 |
|---|---|---|
| **IM** | propagation / coverage | 覆盖大不等于 GU approximation gap 大 |
| **IF / TracIn** | 参数变化、模型状态变化或 held-out/query loss sensitivity | 必须先定义“影响谁”及 source |
| **Hybrid** | coverage + sensitivity | IF 分支不干净时，融合结果也无法干净解释 |

### 3.1 IM 是哪一种近似

当前代码中的 `im` 是 **Independent Cascade spread + Monte Carlo + CELF greedy**。

> [!abstract] 当前 IM recipe
> - **Diffusion model：** Independent Cascade。
> - **Edge propagation：** 默认 `propagation_prob=0.1`。
> - **Spread estimate：** 默认 `mc_rounds=100`；arxiv 常用 `50`。
> - **Greedy optimizer：** CELF lazy greedy；小图默认 batch-CELF。
> - **Candidate pruning：** 小图使用全部 train candidates；arxiv 常用 `candidate_fraction=0.1` 的 top-degree 裁剪。
> - **Selector seed：** `im_selector_seed=2024`，与 GU training seed 解耦。

> [!tip] IM 的结论边界
> IM 近似的是 **传播覆盖**，不是 GU damage，也不是 held-out loss influence。

### 3.2 IF selector 必须先定义“影响谁”

给定候选删除点 $v$：

$$
g_v=\nabla_\theta \ell_v(\theta^*),
\qquad
H=\nabla_\theta^2 L_{\mathrm{train}}(\theta^*),
\qquad
\Delta\theta_v\approx H^{-1}g_v .
$$

符号正负取决于 downweight / upweight 约定；做同一口径排序时，关键是方向与绝对值约定一致。$H^{-1}$ 不显式存储，统一通过迭代 IHVP 求解。

从参数变化变成 selector 时，必须同时固定：

1. 是否指定目标集合 $E$；
2. source 是否包含删除图后的 `grad2` 修正。

#### A/B · target-free 参数变化

> [!info] A
> $$
> A(v)=\lVert g_v\rVert
> $$
> 不指定 $E$。A 是 self-TracIn / gradient-magnitude signal。

> [!info] B
> $$
> B(v)=\lVert H^{-1}g_v\rVert
> $$
> 不指定 $E$。B 是 parameter-displacement reference。

A 与 B 不定义等价；但当前矩阵中 A vs B reference 的 Spearman 为 `0.962`，因此 A 是很强的 **B-ranking proxy**。

#### C · eval-conditioned IF

> [!example] C-point / C-simple
> $$
> C(v;E)=\langle q_v^{\mathrm{IF}},H^{-1}g_E\rangle,
> \qquad
> q_v^{\mathrm{IF}}\in\{g_v,\mathrm{grad1}_v\}.
> $$
> C 指定 $E$，但 source 不含删除图后的 `grad2`。

#### D · graph-aware GIF

> [!important] D-full
> $$
> D(v;E)=\langle q_v^{\mathrm{GIF}},H^{-1}g_E\rangle,
> \qquad
> q_v^{\mathrm{GIF}}=\mathrm{grad1}_v-\mathrm{grad2}_v.
> $$
> D 指定 $E$，并包含完整 graph-deletion source correction。

> [!summary] 最短记忆
> - **A/B：** 不指定 $E$，问梯度多大、参数移动多远。
> - **C：** 指定 $E$，但不含 `grad2` —— IF。
> - **D：** 指定 $E$，并使用 `grad1-grad2` —— GIF。

`grad2` 在同一参数 $\theta^*$ 上对删边图做 forward/backward，不是逐候选 exact retrain。

> [!warning] C/D 是机制分界
> `gt_simple`（C）vs `gt_full`（D）的 Spearman 只有 **0.040**。
>
> 因此 `grad2` 不是可默认忽略的实现细节。

| 机制组 | 是否指定 $E$ | 删除 source | Reference 的核心问题 |
|---|:---:|---|---|
| **A/B** | 否 | $g_v$ | 候选梯度多大；参数预计移动多远 |
| **C · IF** | 是 | $q_v^{\mathrm{IF}}\in\{g_v,\mathrm{grad1}_v\}$ | 候选对目标集合 $E$ 的 IF；不含 `grad2` |
| **D · GIF** | 是 | $q_v^{\mathrm{GIF}}=\mathrm{grad1}_v-\mathrm{grad2}_v$ | 完整 graph deletion 对目标集合 $E$ 的 influence |

### 3.3 组内计算近似是另一条轴

分组固定后，才能比较 reference 与 proxy。

| 组 | Reference | Hessian-free / trajectory proxy | 验证问题 |
|---|---|---|---|
| **A/B** | $\lVert H^{-1}g_v\rVert$ | $\lVert g_v\rVert$；checkpoint self-TracIn | magnitude proxy 是否复现 B 排名 |
| **C-IF** | $\langle q_v^{\mathrm{IF}},H^{-1}g_E\rangle$ | $\langle q_v^{\mathrm{IF}},g_E\rangle$；checkpoint IF-TracIn | 固定 IF source 后，去 Hessian 是否复现排序 |
| **D-GIF** | $\langle q_v^{\mathrm{GIF}},H^{-1}g_E\rangle$ | $\langle q_v^{\mathrm{GIF}},g_E\rangle$；checkpoint graph-TracIn | 固定完整删图 source 后，proxy 是否复现 GIF |

> [!danger] 不要混进正式分组
> - deployed cross-TracIn 使用 training-gradient residual，不使用 $g_E$，只保留为 legacy negative control；
> - degree、PageRank、IM 是 topology anchors；
> - IHVP solver 变体只是实现 sanity check，不单列为 selector。

正式 C/D selector 使用 validation/query set 定义 $E$；test split 只用于明确标注的机制诊断。

当前本地矩阵的三个核心数字：

- **A/B 组内：** A vs B reference = `0.962`；
- **C/D 组间：** C-simple vs D-full = `0.040`；
- **D 组内：** `p_graph` vs `gt_full` = `0.984`。

### 3.4 各名称在分组中的位置

- **gradient norm → A：** $\lVert g_v\rVert$，training-gradient magnitude。
- **parameter displacement → B：** $\lVert H^{-1}g_v\rVert$，target-free 参数位移。
- **point IF → C-point：** $\langle g_v,H^{-1}g_E\rangle$。
- **simple IF → C-simple：** $\langle \mathrm{grad1},H^{-1}g_E\rangle$，不含 `grad2`。
- **graph-aware GIF → D-GIF：** $\langle \mathrm{grad1}-\mathrm{grad2},H^{-1}g_E\rangle$。
- **single-final proxy：** 固定 C 或 D 的 source，只去掉 Hessian。
- **multi-checkpoint TracIn：** 固定 source，累计训练轨迹。
- **deployed cross-TracIn：** legacy control，不归入 A/B/C/D。

Hybrid 若复用 TracIn 分支，其语义也随 source 改变：legacy 分支只能称 legacy Hybrid；C-source 是 coverage + IF sensitivity；D-source 才是 coverage + GIF sensitivity。

## 4. 和 supplementary 实验页的关系

supplementary validity 分成四个问题：

1. **A/B 组内一致性：** A/self-TracIn 是否复现 B parameter-change ranking？
2. **C/D 组内近似：** 固定 IF 或 GIF source 后，proxy 是否复现 reference？
3. **C/D 组间区分：** 加入 `grad2` 后，IF 与 GIF 是否仍选择相同节点？
4. **集合级下游效果：** top-k 集合删除并重训练后，target 与 utility 实际怎样变化？
