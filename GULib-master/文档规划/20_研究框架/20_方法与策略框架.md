# 方法与策略框架

这页放定义。实验页不要再承担方法介绍，否则层级会乱。

TracIn / proper TracIn / GIF / self-influence 的公式边界单独见 [[21_TracIn变体与GIF关系]]；本页只保留总框架。

---

## 1. 两类对象别混

| 对象 | 是什么 | 例子 |
|---|---|---|
| GU method | 执行 graph unlearning 的算法 | GIF / GNNDelete / MEGU / IDEA / GraphEraser / GraphRevoker |
| deletion selector | 决定删除哪些节点的策略 | random / degree / pagerank / IM / TracIn / Hybrid |

实验矩阵是二者交叉：**某个 selector 选择 deletion request，然后某个 GU method 执行 unlearning**。

---

## 2. Selector 的层级

| selector | 类型 | 直觉 | 框架角色 |
|---|---|---|---|
| random | naive baseline | 不带结构和模型信息 | 预算匹配的噪声底线 |
| degree | naive structural | 删除高度数节点，打结构 volume | 最强也最危险的低权限 baseline |
| pagerank | naive structural | 删除全局中心节点 | degree 的全局中心性版本 |
| IM | approximate topology / propagation | 近似最大化传播覆盖 | 检查 coverage signal 是否不同于中心性 |
| TracIn | Hessian-free / trajectory proxy | 依具体 source 近似 A/B、C-IF 或 D-GIF 排名 | 检查 model sensitivity signal；名称必须绑定公式 |
| Hybrid | fused approximation | 融合 IM 与 IF proxy | 检查 coverage + sensitivity 是否互补 |
| GIF | D-group graph-aware reference | 用 `grad1-grad2` 与 `H^-1 grad L_E` 构造完整 graph-deletion influence | 小图上校准 D-GIF proxy |

这里的 naive 不是贬义。degree / pagerank 是必须正面面对的强 baseline；如果它们强，说明结构 volume 本身就是重要发现。

---

## 3. 为什么说 IM 和 IF 都是近似策略

IM 和 IF 都不是“真实攻击效果”的直接读数。它们都是用某个代理目标来挑节点：

| 近似策略 | 代理目标 | 近似什么 | 风险 |
|---|---|---|---|
| IM | propagation / coverage | 删除节点对图上传播覆盖的影响 | 覆盖大不等于 unlearning 近似误差大 |
| IF / TracIn | model-impact 或 loss sensitivity | 删除训练点对模型参数、模型状态或 held-out/query loss 的影响 | 必须先说清楚“影响谁” |
| Hybrid | coverage + sensitivity | 两条代理信号的组合 | 若 IF 分支不干净，融合也不干净 |

### 3.1 IM 是哪一种近似

当前代码里的 `im` 是 **Independent Cascade (IC) spread + Monte Carlo + CELF greedy**：

| 组件 | 当前含义 |
|---|---|
| diffusion model | Independent Cascade，边传播概率默认 `propagation_prob=0.1` |
| spread estimate | Monte Carlo 模拟，默认 `mc_rounds=100`；arxiv 配置常用 `50` |
| greedy optimizer | CELF lazy greedy；小图默认 batch-CELF，加速但仍是近似 |
| candidate pruning | 小图默认全 train candidates；arxiv 常用 `candidate_fraction=0.1` 做 top-degree 裁剪 |
| selector seed | `im_selector_seed=2024`，与 GU training seed 解耦 |

所以 IM 的结论边界是：它近似的是 **propagation / coverage**，不是直接近似 GU damage，也不是直接近似 held-out loss influence。

### 3.2 IF selector 先要定义“影响谁”

IF / GIF 的 model-editing 直觉是成立的：给定候选删除点 $v$，先由训练 loss 定义：

$$
g_v=\nabla_\theta \ell_v(\theta^*),
\qquad
H=\nabla_\theta^2 L_{\mathrm{train}}(\theta^*),
\qquad
\Delta\theta_v\approx H^{-1}g_v .
$$

符号正负取决于把“删除”写成 downweight 还是把“加权”写成 upweight；做同一口径的排序时，关键是方向与绝对值约定一致。$H^{-1}$ 不显式存储，正文统一表述为“通过迭代 IHVP 求解”；具体 solver、HVP 与 probe 设置只属于实现和复现配置。

从“参数会怎么变”变成 selector 时，必须同时固定两个问题：**是否指定目标 $E$**，以及 **source 是否包含删图后的梯度修正**。最终采用 A/B–C–D 三组机制分类：

| 机制组 | 正式目标 | 需要 $E$ 吗 | 需要 $H^{-1}$ 吗 | source / 含义 |
|---|---|---:|---:|---|
| **A/B. target-free parameter-change line** | $A(v)=\lVert g_v\rVert$；$B(v)=\lVert H^{-1}g_v\rVert$ | 否 | B reference 需要 | A 是 self-TracIn/gradient-magnitude proxy；B 是参数移动 reference |
| **C. eval-conditioned IF** | $C(v;E)=\langle q_v^{\mathrm{IF}},H^{-1}g_E\rangle$ | 是 | reference 需要 | $q_v^{\mathrm{IF}}\in\{g_v,\mathrm{grad1}_v\}$，不含删图后的 `grad2` 修正 |
| **D. graph-aware GIF** | $D(v;E)=\langle q_v^{\mathrm{GIF}},H^{-1}g_E\rangle$ | 是 | reference 需要 | $q_v^{\mathrm{GIF}}=\mathrm{grad1}_v-\mathrm{grad2}_v$，包含完整 graph-deletion source correction |

这里的边界必须锁死：

- A 与 B 属于同一条 target-free 线。A 不是 B 的定义等式，但当前矩阵中 A 对 B reference 的全排序 Spearman 为 `0.962`，因此是很强的 **B-ranking proxy**；
- 所有 B/C/D reference 中的 $H^{-1}g$ 都通过迭代 IHVP 求解；solver 变体不单列为 selector 或方法组；
- C 才是普通 eval-conditioned IF：C-point 只用 $g_v$，C-simple 使用原图 affected-set 梯度 $\mathrm{grad1}_v$；
- D 才是 GIF：只有加入删边图上的 $\mathrm{grad2}_v$ 修正后，source 才是 $\mathrm{grad1}_v-\mathrm{grad2}_v$；
- 若 $H$ 对称，$g_E^\top H^{-1}q_v$ 与 $\langle q_v,H^{-1}g_E\rangle$ 等价，因此 C/D 都可以共享求解一次 $H^{-1}g_E$。

可以记成：

```text
A/B：不指定 E，只问候选梯度大不大、参数会移动多远
C：  指定 E，但 source 不含删图后的 grad2 修正 —— IF
D：  指定 E，并加入 grad1-grad2 完整删图 source —— GIF
```

$\mathrm{grad2}_v$ 是在同一参数 $\theta^*$ 上，对删边后的图做 forward/backward；它不是逐候选 exact retrain。C 与 D 的当前全排序 Spearman 只有 `0.040`（`gt_simple` vs `gt_full`），证明 `grad2` 不是可默认忽略的实现细节，而是 IF/GIF 的机制分界。

#### 组内计算近似是独立轴

分组固定后，才比较每组的 reference 与 proxy：

| 组 | Reference | Hessian-free / trajectory proxy | 当前作用 |
|---|---|---|---|
| A/B | B：$\lVert H^{-1}g_v\rVert$ | A/self-TracIn：$\lVert g_v\rVert$；可扩展 checkpoint self-TracIn | 检验 Hessian-free magnitude 是否复现 B 排名 |
| C-IF | $\langle q_v^{\mathrm{IF}},H^{-1}g_E\rangle$ | $\langle q_v^{\mathrm{IF}},g_E\rangle$；checkpoint IF-TracIn | 固定 IF source 后检验去 Hessian近似 |
| D-GIF | $\langle q_v^{\mathrm{GIF}},H^{-1}g_E\rangle$ | $\langle q_v^{\mathrm{GIF}},g_E\rangle$；checkpoint graph-TracIn | 固定完整删图 source 后检验 GIF 近似 |

旧 deployed cross-TracIn 使用 training-gradient residual 而不是 $g_E$，不归入 A/B/C/D，只保留为 legacy negative control。degree/PageRank/IM 同样只是 topology anchors。正式 C/D selector 应使用 validation/query set 定义 $E$；test split 只可用于明确标注的机制诊断。

当前本地矩阵支持这个分层：A 对 B reference 的全排序 Spearman 为 `0.962`；C-simple 对 D-full 仅 `0.040`；固定 D source 后，`p_graph` 对 `gt_full` 为 `0.984`。它们分别回答 A/B 组内 ranking proxy、C/D 组间机制差异与 D 组内 Hessian-free fidelity。IHVP solver 的一致性只作为实现 sanity check 留在复现报告中。

### 3.3 IF / GIF / TracIn 在 A/B–C–D 中的位置

详细学习页见 [[21_TracIn变体与GIF关系]]。这里保留最小定义，避免实验页反复复制。

| 名称 | A/B–C–D 位置 | 分数形式 | 实际含义 |
|---|---|---|---|
| gradient norm | A | $\lVert g_v\rVert$ | training-gradient magnitude control |
| parameter-change IF | B | $\lVert H^{-1}g_v\rVert$ | target-free 参数位移 |
| point IF | C-point | $\langle g_v,H^{-1}g_E\rangle$ | 候选自身对 $E$ 的 IF |
| simple IF | C-simple | $\langle \mathrm{grad1},H^{-1}g_E\rangle$ | 原图 affected-set 对 $E$ 的 IF，不含 `grad2` |
| graph-aware GIF | D-GIF | $\langle \mathrm{grad1}-\mathrm{grad2},H^{-1}g_E\rangle$ | 完整图删除 source 对 $E$ 的 influence |
| single-final proxy | C 或 D 的组内近似 | $\langle q_v,g_E\rangle$ | 固定组别与 source，只去掉 Hessian |
| multi-checkpoint TracIn | C 或 D 的组内近似 | $\sum_c w_c\langle q_v(\theta_c),g_E(\theta_c)\rangle$ | 固定 source，累计训练轨迹 |
| deployed cross-TracIn | legacy / 不归入 A/B/C/D | $\langle g_v,-\sum_{j\in T}g_j\rangle$ | training-gradient residual alignment |

Hybrid 若复用 TracIn 分支，其语义也随 source 改变：legacy 分支只能称 legacy Hybrid；使用 C-source 时是 coverage + IF sensitivity，使用 D-source 时才是 coverage + GIF sensitivity。

## 4. 和 supplementary 实验页的关系

supplementary overlap / validity 需要分四部分：

1. **A/B 组内一致性**：A/self-TracIn 是否复现 B parameter-change ranking？
2. **C/D 组内近似有效性**：固定 IF 或 GIF source 后，proxy 是否复现 reference？
3. **C/D 组间区分度**：加入 `grad2` 后，IF 与 GIF 是否仍选择同一批节点？
4. **集合级下游效果**：top-k 集合删掉并重训练后，validation target 与 test utility 实际如何变化？
