Selection Concordance for GNN Unlearning-Attack Selectors

Do the node-selection strategies pick the same nodes? · GCN, r=0.05, seed 2024 · 5 datasets · generated 2026-06-27 · branch research/selection-concordance-2026-06-27

TL;DR
  • IM does NOT degenerate to degree — set-overlap with degree is low on every dataset (Jaccard 0.1 mean; range 0.05–0.19). The earlier code-level guess that IM≈degree was wrong at the set level: CELF's submodular selection genuinely diverges. (Single-node IM spread can still correlate with degree; the combination differs — as suspected.)
  • degree ≈ pagerank, but dataset-dependent — mean 0.622, range 0.50–0.83 (cora highest). The two cheap centralities are correlated, not interchangeable.
  • TracIn is near-orthogonal to both degree and IM (cora: 0.024 vs degree, 0.029 vs IM). The influence attack targets a genuinely different node set — so "the attack is just degree" is refuted, and since degree wins the attack while sharing almost no nodes with TracIn, the winning signal is structural volume, not influence.
  • GIF-as-scorer: implemented; execution is training-gated (see below).

What this means for the thesis

The selector families are nearly orthogonal: centrality (degree≈pagerank), IM (its own submodular set), and the influence family (TracIn) each target a different node set. Combined with the established result that degree wins the attack on approximate unlearning, this gives set-level evidence for the volume-driven reading: high-influence nodes are not high-damage nodes; the cheap structural centrality is the real lever. It also disposes of two worries — (a) "IM is just degree" (false: 0.05–0.19 overlap), and (b) "you only tested a cheap proxy, not real IF" (TracIn is so orthogonal to degree that it is clearly not degree; the remaining open comparison is TracIn ↔ GIF, the validity check below).

GIF-as-scorer (real influence) — cora (feasibility)

Implemented and demonstrated end-to-end, but INCONCLUSIVE. The efficient IF scorer runs (s=H⁻¹∇L_test via LiSSA, then ⟨s,∇ℓ_v⟩ per candidate), but the only trained cora model on disk — a GNNDelete 3-layer checkpoint — loads into a plain GCN at just 0.34 train accuracy (its deletion-operator forward differs from a plain GCN). Influence computed on a barely-fit model is not a valid surrogate for influence on a well-trained one, so the GIF↔TracIn number below is directional code-validation only, not the validity claim. The clean run needs a properly trained base GCN (AutoDL / un-gated train).

Caveats

  • Single seed (2024), single ratio (r=0.05), single backbone (GCN). Directional, not yet a finished finding — sweep seeds/ratios before publishing.
  • TracIn/Hybrid rows are cora-only: model-based selectors need a trained model, and only cora is cached (others would require training, excluded tonight).
  • IM uses the default IC config (p=0.1, mc=100, im_batch_size=5). The batch-CELF approximation (batch=5) slightly reduces submodular diversity vs classic CELF (batch=1) — re-check with batch=1 before claiming IM's distinctness is intrinsic.
  • Random is included as a near-zero-overlap reference (≈0.02–0.05 with everything), as expected.
